# Compose Nemotron (정량 없는 판)

## 무엇이며 왜 이렇게 하나

`compose-nemotron-panel`과 같은 일을 **정량(설문) 매칭 없이** 한다. 데이터는 비공개 정량×니모트론 1,000명 풀이 아니라 **공개 니모트론 한국 100만 명**(KOSIS·대법원 통계에 정렬된 합성 페르소나)이다. 그래서 앞단(브리프 → 신호 실재 → 세그 → 선발 → 축 합성, 1~6단계)은 `nemotron-panel-synthesis` 절차를 그대로 쓰고, 뒷단(게이트 C 패널 승인 → 7단계 2차 합성 → 8단계 저장소 업로드)은 **컴포즈 구조**를 쓴다.

정량이 없으니 지켜야 할 것 하나: **니모트론에 없는 개인 사실은 사실이 아니라 `[가설]`이다.** 브랜드 이력(과거·현재·다음 컴포즈 의향), 커피 이용 디테일, SNS 이용 플랫폼이 여기에 들어간다. 지우지 않고 남기되 FGD에서 흔들 질문(`fgd_probe`)을 붙인다 — 결과의 방어 가능성은 그 경계가 드러나는 데서 나온다.

핵심 철학은 같다: **믿게 만들지 말고 검증 가능하게 만든다.** 세그는 실재해야 하고, 인물은 uuid로 원본 대조가 되며, 합성 속성은 provenance 태그로 근거의 두께가 드러나야 한다. 산출 `personas_fused.json`은 `persona-qual-fgd`가 그대로 참여자로 소비한다(FGD는 이 스킬이 하지 않는다).

## 의존성 — 먼저 확인

데이터는 **두 경로 중 하나**로 연다. 어느 쪽이든 리더가 읽는 바이트는 원본과 동일하다(아래 '원격 모드의 동일성' 참고). **로컬 원본이 없다고 진행을 멈추지 않는다** — 원격으로 연다.

- **로컬 모드** — 연결된 폴더에 `nemotron.parquet`(약 2.85GB, 100만 행, Hugging Face `nvidia/Nemotron-Personas-Korea`)가 있으면 그걸 쓴다. 파일명이 `file`처럼 확장자가 없으면 `.parquet`로 바꾸게 안내.
- **원격 모드(기본 폴백)** — 연결된 폴더가 없거나 파일이 없으면 GitHub **공개** 저장소 `untitled84/nemotron-data`에서 **필요한 구간만** 받는다. 저장소 연결·로그인·토큰은 필요 없다 — `raw.githubusercontent.com`에서 받고, 막히면 `gh` CLI로 재시도한다. 둘 다 실패하면(네트워크 허용 목록에 GitHub이 없는 환경) 진행하지 말고, 사용자에게 로컬 원본 연결 또는 GitHub 접근이 되는 세션을 요청한다.
- `scripts/nemotron_reader.py` — 순수 파이썬 리더(pyarrow 불필요). 샌드박스는 PyPI/npm 접속이 막혀 있을 수 있으니 pyarrow/duckdb 설치를 시도하지 말 것 — 동봉 리더로 충분하다.
- **스크립트·참고 파일·2차 합성 자료는 전부 저장소에서 받는다** — 이 스킬 폴더엔 SKILL.md만 있다. 시작할 때 한 번:
  ```bash
  git clone --depth 1 --filter=blob:none --sparse https://github.com/untitled84/nemotron-data && \
    git -C nemotron-data sparse-checkout set skill_scripts references fusion
  # git이 막히면: 같은 경로를 raw.githubusercontent.com/untitled84/nemotron-data/main/<경로> 로 하나씩 받는다
  #   (파일 목록 = https://api.github.com/repos/untitled84/nemotron-data/git/trees/main?recursive=1 , 실패 시 gh api 로 재시도)
  cat nemotron-data/skill_scripts/VERSION nemotron-data/fusion/scripts/VERSION   # 사용자에게 한 줄로 알린다
  ```
  이후 `work_scripts` = `nemotron-data/skill_scripts`(니모트론 리더·스캔·선발·감사·렌더), `work_refs` = `nemotron-data/references`, 2차 합성 = `nemotron-data/fusion/scripts`(`fusion.py`·`external.py`·`trends.py`)와 `fusion/trends/`·`fusion/external/`. **parquet 조각(`parts/`)은 clone하지 않는다** — 리더가 필요한 조각만 원격으로 받는다. 받기가 둘 다 실패하면 진행하지 않고 GitHub 접근이 되는 세션을 요청한다.

리더 로드 확인 — **항상 `open_nemotron`으로 연다**(로컬 경로가 있으면 로컬, 없으면 원격을 자동 선택):
```python
import sys; sys.path.insert(0, "nemotron-data/skill_scripts")
from nemotron_remote import open_nemotron
npq = open_nemotron("<folder>/nemotron.parquet")   # 로컬이 없거나 경로를 모르면 open_nemotron()
print(type(npq).__name__, npq.num_rows, npq.num_row_groups)   # ... 1000000 / 72
```
`npq`의 API(`read_column`·`load`·`load_adaptive`·`num_rows`)는 두 모드에서 같다. 이후 본문의 `NemotronParquet(...)` 예시는 전부 `open_nemotron(...)`으로 읽는다.

**원격 모드의 동일성.** 원본 parquet을 재인코딩 없이 바이트 구간 146조각(`head` · rg별 구조형 35컬럼 `rgNN_s`(약 0.7MB) · 서술형 16컬럼 `rgNN_t`(약 39MB) · `footer`)으로 잘라 올렸다. 로더는 원본 크기의 희소 파일을 만들고, 읽으려는 컬럼이 속한 조각만 받아 원래 offset에 쓴 뒤 같은 리더로 읽는다. 조각마다 sha256을 검증한다. 2026-10-16 검증(인증 없는 공개 경로 재검증 포함): 조각 전체 재조립 sha256 = 원본 sha256, 3개 rg × 51컬럼 + 72rg × 구조형 4컬럼 441건 값 일치, `load_adaptive`·`signal_scan --deep` 출력 완전 일치.

**원격 모드 비용(첫 실행 기준).** 열기 12.6MB(footer). 구조형 72rg 전수(모집단 스케일) ≈ 52MB·약 8초 — 전수 전에 `npq.prefetch(range(72), "struct")`로 병렬로 받는다. 서술형은 rg당 약 39MB(약 2~3초). 받은 조각은 캐시(`~/.cache/nemotron`)에 남아 같은 세션에서 다시 받지 않는다. 그래서 **'필요한 rg만 읽는다'는 아래 규율이 원격 모드에선 다운로드량 규율이기도 하다.**

## 실행 흐름 (게이트 3개 — A·B·C에서 반드시 멈춘다 · 1~6단계 = nemotron-panel-synthesis 절차, 게이트 C·7·8단계 = 컴포즈 구조)

### 1단계 · 브리프 파싱
업로드된 브리프에서 카테고리·브랜드·과제·타깃을 뽑는다. `pdftotext -enc UTF-8`로 먼저 시도하고, **텍스트가 거의 안 나오면 이미지 기반 덱**이다 — `pdftoppm -png -r 130`으로 페이지를 렌더해 **시각으로 읽는다**(tesseract는 한국어 학습데이터가 없어 OCR 불가). 40p 넘는 대형 덱은 PIL로 컨택트시트(썸네일 그리드)를 만들어 전체를 훑고 핵심 슬라이드만 정독하면 빠르고 컨텍스트도 아낀다. 브랜드/시장 사실이 필요하면 **웹서치로 근거화**한다(제품 라인·포지셔닝·점유율·구매 동기 등). 이건 뒤 세그 가설이 "실재하는지" 대조하기 위한 필수 단계다.

**브리프 뒤집기 렌즈 (경량 리버스씽킹) — 받아 적기 전에 한 번 뒤집는다.**

브리프를 그대로 받아 적기만 하면 세그가 **브리프의 상상력 안에 갇힌다** — 클라이언트가 이미 아는 타깃만 다시 보여주는 패널이 된다. 파싱을 마친 뒤 세 각도로 뒤집어 본다:

- **타깃 반전** — 브리프가 지목한 타깃의 반대편·이탈자·경계인은 누구인가. (헤비유저 브리프 → 최근 이탈자·경쟁 브랜드에서 넘어올 뻔한 사람 / 신규 유입 브리프 → 알면서도 안 사는 사람)
- **전제 의심** — 브리프가 당연시하는 구매 동기·장벽이 데이터에서도 당연한가. 당연시된 전제를 **2단계에서 검증할 질문**으로 바꾼다. (브리프: "가격이 장벽" → 정말? finance_persona에서 가격 신호 없이 다른 장벽이 큰 층이 있나 스캔)
- **인접 침입** — 카테고리 밖 어떤 행동축이 이 과제의 진짜 변수인가. 4단 사다리 2번(축 재정의)과 같은 근육인데, 거긴 신호가 없을 때 타는 비상구고 **여긴 신호가 있어도 한 번 돌린다.**

이 렌즈는 발산이 목적이 아니다 — **역발상 세그 후보 1~2개**를 만들어 2단계 스캔에 태우는 것까지가 역할이다(한 줄씩이면 충분, 발산 문서를 만들지 마라). 브리프의 문제 정의 자체를 다시 쓰는 깊은 작업이 필요하면 그건 `reverse-thinking` 스킬의 영역이다.

### 2단계 · 신호 실재 검색 (합성 전 필수)

브리프의 핵심 타깃 속성(팬덤·브랜드·카테고리 관심 등)이 **니모트론에 실제로 있는지 데이터에서 먼저 검색한다.** 지어내기 전에 확인하는 이 단계가 이 스킬의 방어선이다 — 있으면 근거 있는 패널을 만들고, 없으면 "이 데이터로는 못 만든다"고 말한다. 없는 걸 있다고 가정하고 넘어가는 순간 뒤의 모든 산출이 오염된다.

**역발상 세그 후보(1단계 뒤집기 렌즈 산출)의 신호도 정방향과 같은 절차·같은 오탐 규율로 스캔한다.** 뒤집기는 자유지만 제안은 실재할 때만 한다 — 이게 이 스킬의 리버스씽킹이 원조 스킬과 다른 점이다.

방법: `hobbies_and_interests_list` + `arts_persona` + `persona` 텍스트를 키워드로 훑고 **풀 규모를 센다**. 탐색은 rg 1~2개(1.4~2.8만 명)로 빠르게 하되, **그 결과를 100만 행 기준으로 환산해 보여준다**(rg 1개는 전체의 1.4%다 — "41명"이 아니라 "41명 → 니모트론 내 환산 약 2,900명"이라고 말해야 사용자가 N을 정할 수 있다).

**환산 수치는 니모트론 100만 명 안의 수치다 — 한국 인구가 아니다. 게이트 A에서 반드시 그렇게 부른다.** 니모트론 서술형은 LLM이 센서스 속성을 보고 쓴 글이라 주제마다 실제와 다르게 잡힌다(실측 2026-10: 20대 인스타그램 언급 3.4% vs 실제 이용률 80.9% / 20대 게임 33.9% vs 85.2% / 등산·흡연은 근사). `references/calibration.md`에 축별 **니모트론 언급률 vs 공공 통계** 비율이 있고, `signal_scan.py`가 키워드가 그 축에 해당하면 자동으로 함께 찍는다. 그 행을 **환산 수치 옆에 그대로 보여준다**. 비율 0.5 미만(니모트론이 적게 잡는 축)이면 ① 실제 풀은 환산보다 크다고 말하고 ② **그 축에서는 "신호 부재"를 선언하지 않는다** — 4단 사다리를 타기 전에 그 부재가 데이터의 사각인지부터 적는다. 표에 없는 축은 "외부 통계 미확인"이라고 말하지, 모델 기억으로 수치를 채우지 않는다. 신호가 희소해 판단이 애매하면 rg를 늘려 다시 센다. **rg 1~2개면 비율 추정에 충분하다**(근거는 5단계). 교차 조건이 캠페인의 핵심이면(예: K-pop 팬 × 게이머) **교집합 크기도 반드시 센다** — 거기가 보통 캠페인의 심장이다.

**오탐은 두 종류다 — 섞으면 둘 다 못 잡는다.**

**(a) 문자열 오탐** — 다른 단어에 부분 매칭. '라이브'는 **'드라이브'에 걸린다**(실측: 836건 중 803건, **96%가 오탐**이었다). → `--exclude-prefix 라이브=드`로 앞글자를 배제한다.

**(b) 의미 오탐** — 단어는 정확히 맞는데 **지시 대상이 다르다. 이게 더 위험하다.** 배제 규칙으로는 원리적으로 못 잡고, 카운트가 커 보여서 게이트 A의 풀 규모를 통째로 허수로 만든다. 실측:
- **'쇼핑'(6.1%)은 대부분 백화점·아울렛 오프라인**이었다 — 온라인 커머스 브리프에서 이걸 그대로 썼으면 엉뚱한 사람들로 패널을 채웠다.
- **'네이버'(2.63%)는 블로그·웹툰·지도**였다 — 네이버쇼핑이 아니다.

플랫폼명·채널명·다의어 카테고리 용어(쇼핑·검색·구독·리뷰)는 (b)를 **기본으로 의심한다**.

**절차**: 무작위 문맥 샘플 **10개 이상**(앞 5개가 아니다 — first-N은 분포 표본이 아니라 우연히 다 과녁이면 "오탐 없음"으로 오판한다)을 과녁/비과녁으로 분류하고, **과녁 비율을 곱해 보정한 카운트**를 게이트 A에 낸다: *"쇼핑 974명, 그중 온라인 맥락 2/10 → 유효 풀 ~195명"*. **과녁 비율 30% 미만이면 그 키워드는 버리고** 더 좁은 표현('네이버쇼핑'·'최저가'·'장바구니')으로 다시 스캔한다. **세그 그물이 정규식이면(references/net_patterns.md) 같은 스크립트에 `--re`·`--re2`·`--neg`·`--body`로 그대로 넣는다** — 손으로 스캔 스크립트를 따로 짜면 환산·보정표 출력이 빠진다.

검색 결과(신호별 풀 규모 + 문맥 샘플)는 **게이트 A에서 사용자에게 그대로 보여준다.** 세그가 실재한다는 증거이자, 사용자가 N을 정할 때 필요한 정보다.

**부재를 선언하기 전에 — 스캔 범위부터 넓혀라.** 기본 스캔은 서술형 13개 중 3개(`hobbies_and_interests_list·arts_persona·persona`)뿐이다. "신호가 없다"는 이 스킬의 방어선이자 세그 설계를 통째로 바꾸는 판정인데, 그걸 3/13 위에서 내리면 **부재가 스캔 범위의 아티팩트**일 수 있다. AI 활용은 `professional_persona`에, 돈·가격 행동은 `finance_persona`에 산다.

> **규칙**: 신호가 **1% 미만으로 나오거나 '부재'를 선언하려면**, 그 전에 반드시 `signal_scan.py --deep`(서술형 11컬럼)으로 재확인한다. rg 1개면 확장해도 몇 초다. **부재 선언 시 근거가 된 컬럼 목록을 게이트 A에 병기**한다.
>
> 실측: 네이버 브리프의 'AI'는 3컬럼에서 5명이었는데 `--deep`에서 12명으로 2배 넘게 늘었다. 결론(0.09%, 여전히 부재)은 같았지만, **결론이 같다는 것과 근거가 있다는 것은 다르다.**

**신호가 정말 없으면 — 순서대로 4단 사다리를 탄다. 곧장 포기하지 마라.**

1. **직접 신호 재탐색** — `--deep` 확장 + 더 좁은/넓은 표현으로 다시 스캔. **보정표에서 그 축이 '과소'면 사다리를 타기 전에 게이트 A에 "니모트론이 적게 잡는 축이라 부재가 데이터 사각일 수 있음"을 먼저 적는다.**
2. **축 재정의** ← *네이버에서 실제로 통한 길이다.* 브리프의 **조사 질문을 니모트론에 실재하는 인접 행동축으로 번역**한다. 예: 'AI 인지'는 데이터에 없지만(0.10%), Level 3의 진짜 질문인 **"결정을 남에게 넘길 것이냐"**는 `finance_persona`·`detailed_persona`에 **행동으로** 있다 → **'위임 저항'** 축(가격 사냥꾼=직접 탐색이 통제 / 편의 위임파=이미 배달앱·구독에 위임 중). 신기술·신카테고리 브리프에서 주인공 신호가 데이터에 없는 건 **예외가 아니라 기본값**이다.
   - 재정의는 프록시보다 근거가 두껍다(실재 행동이니까). 하지만 **질문을 바꿔치기하는 별도의 리스크**가 있고, 그 승인 권한은 나에게 없다.
   - **(a) 게이트 A에서 번역문을 그대로 보여주고 사용자가 판단하게 한다**: *"원래 물으려던 X(AI 수용도)를 이 데이터에선 Y(위임 저항)로 잽니다. 대리로 인정하시겠습니까?"*
   - **(b) 산출물에 "X축은 Y로 대리 측정됨"을 명시한다.**
3. **프록시** — 예: PUBG 유저 → 게임·롤·스팀 신호. **근거가 얇다는 걸 카드에 밝힌다.**
4. **불가 선언** — 이 데이터로는 못 만든다고 말한다. 이게 정답인 경우가 있다.

실사례: PUBG×IVE 브리프에서 "아이돌 팬 근거가 없다"는 통념과 달리 rg0에 아이돌 123명·뉴진스 202명이 실재했고, K-pop×게이머 교차층도 62명 있었다. 검색해봤기 때문에 지어내지 않고도 패널을 만들 수 있었다.

### 3단계 · 세그 가설 추천  `[게이트 A]`
브리프 + 웹서치로 확인한 브랜드/시장 현실에서 **실재하고 검증 가능한** 세그 가설을 제안한다. 세그는 그 브랜드의 실제 제품·포지셔닝 구조에서 도출해야 한다(임의 분류 금지). 각 세그마다 다음을 붙여 제시하고 **멈춘다**:

- **판별 기준**(진입 동기)
- **데모 경향**(연령·지역·소득 등)
- **니모트론에서 잡을 신호**(어떤 필드/텍스트로 이 세그를 필터링할지)

**판별 기준은 니모트론에서 관찰 가능한 행동으로 번역돼야 세그다 — 하드 필터는 그 행동, 데모는 가점.** 첫 실전(BEREX)에서 '검증된 브랜드를 당연히 고르는 헤리티지 보수형'을 자가+고소득(데모)으로 거르고 브랜드 키워드를 가점으로 뒀더니, 뽑힌 3명 중 판별 기준을 실제로 보이는 사람은 1명이었다. 데모로 거르면 "고소득 가정"이 나오지 "검증된 것만 사는 사람"이 나오지 않는다. 순서를 뒤집어라: ① 판별 기준을 서술형에서 잡히는 행동 문장으로 바꾼다('검증된·내구성·오래 쓰는 것에 투자'는 finance_persona에 있다) ② 그 행동 키워드가 **하드 필터** ③ 연령·소득·주거는 **가점**. 번역이 안 되는 세그(브랜드 선택·구매 이력처럼 데이터에 없는 행동)는 게이트 A 표와 AskUserQuestion 보기 설명에 **"데모 프록시 세그 — 적합 검증 불가"**를 붙여 사용자가 알고 고르게 한다. 조용히 데모로 대체하지 마라.

**역발상 세그 1~2개를 `[역발상]` 라벨로 함께 제안한다.** 1단계 뒤집기 렌즈에서 나온 후보 중 **2단계 신호 스캔을 통과한 것만** — 정방향 세그(브리프의 문제 정의를 따르는)와 라벨로 구분하고, **어느 뒤집기 각도에서 나왔는지 + 왜 이 브리프에 값어치가 있는지**를 한 줄 붙인다. 규율은 정방향과 완전히 동일하다(판별 기준·데모·신호 첨부, 실재 검증). 통과한 후보가 없으면 억지로 만들지 말고 *"역발상 후보 X·Y는 신호 부재로 제외"*를 게이트 A에 기록한다 — 제외 기록 자체가 정보다. 역발상 세그의 값어치는 FGD에서 정방향 세그와의 **대비**다: 브리프의 전제가 어느 세그에서 깨지는지 보는 것. 사용자가 안 고르면 그대로 버린다 — 권할 뿐 강요하지 않는다.

규칙: 세그를 규정하는 것 자체는 합성(날조)이 아니다 — 단 "실재하고 측정 가능"해야 한다. 웹/통계로 존재·규모·데모를 대조할 수 없는 범주는 만들지 않는다. 자세한 근거 규칙은 `references/provenance.md` 참조.

**세그 표를 보여준 뒤 반드시 `AskUserQuestion`으로 묻는다 — 산문으로 "결정해 주세요"로 끝내지 않는다.** 사용자가 눌러서 고를 수 있어야 게이트다. 한 번의 호출에 아래 질문을 함께 넣는다(최대 4개):
1. **세그 선택** — `multiSelect: true`, 보기 = 제안한 세그 각각(라벨에 세그명, 설명에 판별 기준 한 줄 + 풀 규모). `[역발상]` 세그도 보기에 넣는다. 추천 조합은 첫 보기에 "(Recommended)".
2. **세그당 N** — 3명(Recommended) / 2명 / 4명.
3. **연령대** — `multiSelect: true`, 보기 = 20대 / 30대 / 40대 / 50대 이상. 브리프 추론 기본값에 "(Recommended)"를 붙이고 설명에 근거 한 줄. (4단계의 연령 규칙을 여기서 받는다.)
4. **대리 측정 축 승인** — 2단계에서 축 재정의가 나왔으면(예: '월정액 저항/수용' = 렌탈 수용도 대리) 넣는다/넣지 않는다. 없으면 이 질문은 생략.
사용자가 "Other"로 자유 입력하면 그 내용을 세그·N·연령에 반영하고, 세그 수정·추가 요청이면 표를 고쳐 **다시 한 번 묻는다**. 답이 오기 전에는 5단계로 가지 않는다.

### 4단계 · 사용자 확정  `[게이트 B]`
사용자가 세그를 고르고(복수 가능), **세그당 인원 N**, **연령대**를 정한다. 세그 수정·추가도 받는다. 확정 전엔 매칭으로 넘어가지 않는다.

**연령대는 반드시 사용자가 정하게 한다 — 조용히 내가 정하지 않는다.**

연령은 결과를 가장 크게 흔드는 축이다. 그런데 초기 실행에서 나는 매번 임의로 잡았고(PUBG 19–29, GB6 19–24, 비데 25+) **사용자는 그걸 몰랐다.** 같은 브리프도 연령대를 어디로 잡느냐에 따라 완전히 다른 패널이 나온다.

- **제시 형식은 연령대 보기 + 복수 선택이다.** 자유 입력이나 범위 묶음(예: "20~40대", "전체 성인")으로 물으면 **사용자가 원하는 조합을 만들 수 없다.** 아래를 보기로 주고 **복수 선택**을 받는다:

  | 보기 | 범위 |
  |---|---|
  | 20대 | 19–29 (니모트론 하한이 19세라 20대는 19부터) |
  | 30대 | 30–39 |
  | 40대 | 40–49 |
  | 50대 이상 | 50+ (상한을 주면 그대로 — 예: 50~69) |

  20대+30대만, 40대+50대이상만, 20대+50대이상(양극 대비) 같은 조합이 실무에서 흔하다. 필요하면 더 잘게(예: 대학생 19–24) 받는 것도 열어둔다.
- **브리프에서 추론한 기본값은 '추천'으로 표시만 하고 강제하지 않는다.** 예: 대학생 타깃 → 20대 추천 / 가구 구매재 → 30·40·50대 이상 추천 / 앱테크 → 40·50대 이상 추천. 근거(브리프 문장·카테고리 구매 연령)를 한 줄로 붙인다.
- **전체 공통이 기본**이지만, **세그별로 다르게 잡아야 하는 경우도 흔하다** — 대학생(19–24) + 학부모 결정자(40–55)를 한 패널에 담는 식. 그럴 땐 세그마다 범위를 따로 받는다.
- **니모트론 하한은 19세**다(규칙 6). 10대 타깃 브리프면 여기서 다시 고지하고 학부모 대리를 제안한다.
- 연령대를 좁히면 풀이 급격히 줄어든다. 세그 조건까지 겹쳐 N이 안 차면 5단계에서 row group을 확장한다(2단 방식).
- **연령을 한 대로 좁히면 '인지 경계'의 대비가 급감한다.** WRTN(20대만)에서 9명 전원의 AI 인지 경계가 동일하게 나와 분기가 죽었다. **경계 대비가 곧 조사 질문인 브리프**(AI 진입장벽, 신기술 수용, 세대 격차 등)라면 **연령 조합을 권한다** — 20대+50대 이상으로 뽑으면 "챗지피티 같은 건가요?" vs "그건 티비에서 본 건데"로 갈리고, 그제야 '진입장벽'이 관찰 가능해진다. 권할 뿐 강요하지 않는다.

- **그러나 '권고'로 끝내지 말고, 대가를 수치로 한 번 예고한다.** 정성적 경고("대비가 급감한다")는 흘러간다. 니모트론 스캔은 게이트 B **전에** 이미 끝나 있으니, 사용자가 단일 연령대를 고르는 순간 그 선택이 만들 쏠림을 **미리 계산해 보여줄 수 있다**:
  > *"20대만 선택하시면 디지털 접점 분포상 'AI 인지 경계' 최빈값 점유율이 ~56%로 예상됩니다(접점 5+ 3.5% vs 50대+ 1.0%). 이 브리프의 조사 질문인 '진입장벽'이 관찰되기 어렵습니다. 그래도 진행할까요?"*

  **한 번 묻고, 확정하면 존중한다. 재차 설득하지 않는다.** 이 질문도 `AskUserQuestion`으로 — 보기는 "선택 유지(감수)" / "세그별로 다르게" / "추천 조합으로". 예고 수치는 질문 앞 산문에 둔다.

- **감수 확정된 쏠림은 도장이 아니다 — 규칙 충돌을 여기서 끊는다.** 사용자 선택이 6단계 도장 기준(≥78%)을 넘기면 "고치기 전엔 산출하지 않는다"(6단계)와 "권할 뿐 강요하지 않는다"(여기)가 **정면 충돌**한다 — 고치려면 사용자 확정을 뒤집어야 하기 때문이다. 해소: 예고를 받고 감수하기로 한 축은 **'기록된 트레이드오프'**로 분류하고(`axis_audit.py --accepted "<축이름>"`), 산출물에 그 사실과 수치를 명시한 뒤 통과시킨다. (6단계 예외 3번)

**베이스 + stance 구조**: 사용자가 한 세그를 "리크루팅 기준(베이스)"으로 지정하고 나머지를 그 안의 stance로 쓰길 원할 수 있다(예: 베이스=대학생, 그 안에서 맥북/그램/갤럭시에코). 이 경우 베이스는 **전체 풀에 거는 필터**로, 나머지는 그 필터 안에서 나누는 **하위 stance**로 처리한다. 실무에서 흔한 요청이니 먼저 물어보면 좋다.

### 5단계 · 캐리어 매칭 (2단 방식)
`nemotron_reader.py`로 parquet를 디코딩해 세그 조건에 맞는 **실제 행**을 뽑는다.

**컬럼은 다 읽되, 행은 필요한 만큼만 읽는다.**

두 번 틀렸다. 처음엔 5회 실행 전부 `rg_indices=[0]`(1.4%)만 썼고, 그걸 고치면서 "항상 100만 전수"로 과보정했다. **둘 다 틀렸다.**

핵심은 **니모트론이 인구정렬 데이터라 row group마다 분포가 같다**는 것이다. rg0의 13,909명은 이미 100만의 축소판이다. 그러니 **흔한 조건은 rg 1개로 충분하고, 희소한 조건만 확장이 의미 있다.** 실측:

| 세그 | 목표 후보 60명을 채우는 데 |
|---|---|
| 20초 여성 뷰티 고관여(흔함) | **rg 1개 · 1.4%** |
| 아이브 실청취 19~29(희소) | **rg 2개 · 2.8%** |
| (참고) 텍스트 컬럼 72rg 전수 | rg 1개의 **두 자릿수 배** — 거의 항상 낭비다 |

**그래서 적응형으로 읽는다** — `nemotron_reader.load_adaptive(columns, filter_fn, min_rows)`가 rg를 하나씩 늘려가며 조건 충족 행이 목표에 닿으면 **멈춘다**.

- **후보 풀 최소 = 세그당 N의 20배**(N=3이면 60명). 그 미만이면 뽑을 게 없어 아무나 집는 것과 같다.
- 목표를 못 채운 채 72rg를 다 읽었다면 그 세그는 **이 데이터로 너무 희소한 것**이니 게이트로 돌아가 알린다 — 조용히 부실한 3명을 내놓지 않는다.

**단계별 비용 원칙:**
- **모집단 파악용 구조형**(`age, sex` 등 2~5컬럼)은 **72rg 전수해도 1.8초**다. 게이트에서 "19~29 여성 69,328명" 같은 실제 스케일을 보여주는 값어치가 있으니 이건 전수한다.
- **텍스트 스크리닝**(취미·arts_persona)은 비싸다 → **적응형**.
- **서술형 13개**는 가장 비싸다 → **선발된 인물이 속한 rg만** 읽는다(`read_column(rg, col)` + 오프셋). 9명 뽑는데 100만 행 서술형을 읽지 마라.

**더 읽는다고 좋아지지 않는 경우가 있다 — 스코어 천장.** 노스카나에서 상위 3명 점수가 `[15, 15, 15]` 동점이었다. 스코어 함수가 정수 키워드 카운트라 천장에 닿은 것이다. 이러면 rg를 늘려도 **같은 점수인 사람만 늘어난다.** 답은 확장이 아니라 **스코어를 정교하게 만드는 것**(가중치·연속값·t점수 활용)이다. 상위 N이 동점이면 확장을 멈추고 스코어를 고쳐라.

리더는 72개 row group 전부에서 검증됐다(576건 전수 통과). 필요하면 언제든 확장할 수 있다 — 다만 대개 필요 없다.

각 세그 안에서 신호 스코어링(직업·소득·가구·성격·건강·취미 텍스트 키워드)으로 후보를 줄이고, **점수 상위 K명(기본 15명)의 원문을 읽어 확정**한다(아래 '읽기로 확정'). 스코어링 로직은 세그마다 다르므로 프로젝트에 맞게 인라인으로 작성한다. 선발 인물엔 **uuid를 반드시 보존**(원본 대조용).

#### 그물과 읽기의 분업 — 키워드는 재현율, 읽기는 정밀도

BEREX 실측(500명을 LLM 심사자가 원문으로 채점)에서 확인된 것: **키워드 그물로 재현율은 올릴 수 있지만 정밀도는 못 올린다.** 그물을 넓히자 재현율이 B 40→96%, D 43→83%로 올랐다. 반면 정밀도는 튜닝에 쓴 표본에선 올라 보였다가(과적합) 새 표본에서 원위치였다 — 오탐이 매번 새 문맥('검증된 **적금**'·'검증된 **빌드**'(게임)·'검증된 **맛집**'·'검증된 표준 **매뉴얼**'(업무))으로 나와 두더지잡기가 된다. 그래서 일을 나눈다.

**① 그물(하드 필터) 작성 규칙 — 넓게, 제외는 패턴으로만.**
- 판별 기준 행동의 **동의 표현을 넓게** 넣는다. 한 단어로 그물을 치면 진짜의 절반을 놓친다(BEREX D: '최저가·가성비·핫딜' 7개 → 진짜의 43%. "가격을 따진다·마감 세일·할인 쿠폰·시세 비교·단돈 만 원"을 넣자 83%).
- **두 조건 교집합 세그(수면×기기, 통증×회복)는 조건마다 따로 넓힌다.** 기기 조건을 'IT 기기·가전제품' 단어로 묶었더니 진짜 B("잠들기 전 팟캐스트에 의지", "유튜브 명상 음악", "태블릿 퍼즐 게임")를 다 놓쳤다(재현율 40%). 몸 조건도 '근육·허리'만으론 '무릎이 쑤심·찌뿌듯·굳은·결림·파스'를 놓친다.
- 제외는 **반복되는 문맥 패턴**만 정규식으로: 비유("밤잠을 설칠 **정도로/만큼**"), 금융 목적어("검증된 **저축·적금·방식**"), 비유적 형용("튼튼한 **경제적 성벽**"). 새 오탐 단어를 하나씩 잡으려고 그물을 계속 고치지 마라 — 그건 ②의 일이다.
- 수면·건강 같은 신체 서사 조건은 **신체·일상 컬럼(healthcare·detailed·persona·family·professional)에서만** 찾는다. finance_persona의 "잔고 걱정에 밤잠을 설친다"는 돈 이야기다.

**② 풀 점검 게이트 — 읽어서 '0점 비율'을 잰다.** 그물이 만든 후보 풀 — **실제로 선발·핸드오프할 그 풀**(같은 그물, 같은 rg) — 에서 **무작위 25명**(앞 25명 아님)을 읽고 각자 판별 기준에 0/1/2로 매긴다: 2=기준 행동이 원문에 명시 / 1=한쪽 조건만·태도 수준 / **0=없음 또는 키워드 문맥이 다름**. 지표는 **0점 비율**이다. 2점 비율은 쓰지 마라 — 같은 기준인데 심사자(LLM)에 따라 B를 22%→8%, C를 68%→40%로 다르게 봤다. 1점/2점 경계는 판단마다 흔들리고, 0점(아예 아님)은 안정적이다.
```python
from selection import log_pool_check
log_pool_check(rec, judged={uuid: 0|1|2, ...}, mode="sampled"|"full_read"|"top_read", note="<0점 문맥 패턴>")
```
**점검은 실제 선발 풀에서 한다.** 다른 rg나 다른 버전 그물로 잰 0점 비율은 그 풀의 숫자가 아니다. BEREX에서 rg1 풀로 잰 A의 0점은 24%였는데, 패널이 나온 rg0 풀을 전수 읽어보니 34%였다 — 인구정렬이라 분포가 같다는 가정은 구조형 필드에선 맞아도 표본 25명의 오차까지 없애주진 않는다. 그물을 고치거나 rg를 늘리면 풀이 바뀐 것이니 점검을 다시 한다. `audit_selection`이 읽은 사람이 선발 풀 밖이면 🔴로 막는다.
- **0점 ≤15%** → 풀 그대로 사용(`mode="sampled"`).
- **0점 >15% 이고 풀 ≤400명** → **풀 전수 읽기**(`mode="full_read"`): 0점을 풀에서 빼고 남은 풀로 선발·2-b 핸드오프. 100명 ≈ 17만 토큰, 감당된다. BEREX A(풀 157명, 0점 24%)가 여기에 해당.
- **0점 >15% 이고 풀 >400명** → 전수는 비싸다. 그물에서 반복 오탐 패턴을 ①의 제외 규칙으로 한 번만 고치고 다시 25명을 잰다. 그래도 넘으면 **점수 상위 400명만 읽어**(`mode="top_read"`) 그 안을 풀로 쓰고, 핸드오프에 "풀 = 상위 400 중 적합자, 하위는 미검증"을 적는다.
- 0점 비율은 `selection_log`에 남고 `audit_selection`이 본다: **2-b로 넘길 패널인데 풀 점검이 없으면 🟡, 0점 >15%인데 `mode="sampled"`면 🔴.** 0점이 섞인 풀을 룩어라이크에 넘기면 "이 세그가 실제 소비자 중 몇 %"가 그 비율만큼 부풀고, 진짜가 아닌 사람(금융 보수파·돈 걱정하는 사람)에게 실제 응답자가 매칭된다.

**③ 읽기로 확정 — 12명은 점수가 아니라 원문으로.** 점수 상위 K명(기본 15명, 풀 전수 읽기를 했으면 그 결과)의 원문을 읽어 적합(2점)/근접(1점)/탈락(0점)을 나누고, **적합 중에서** 아래 다양성 최소 규칙을 맞춰 N명을 고른다. 점수는 후보를 줄이는 용도다. 이렇게 고르면 점수 순위 밖에서 뽑는 일이 생기는데 정상이다 — 그 사유(예: "상위 3명이 같은 여자·자가·550만+ 프로필")를 `note`에 쓴다. 판단의 근거는 아래 `fit_quotes`다.

**교집합 세그(두 조건, 예: 수면×기기·통증×회복)의 2점 = 두 조건이 그 사람 텍스트 어디든 명시적으로 있음.** 같은 문장일 필요는 없다(같은 문장에 있는 사람은 드물다 — BEREX B는 풀의 8%). 한쪽만 있으면 1점. 이때 `fit_quotes`는 두 문장을 ` / `로 이어 적는다.

**선발 우선순위 — 위가 아래를 이긴다:**
1. **세그 적합(2점, 원문 인용)** — 절대. 다른 무엇 때문에도 2점을 빼고 1점을 넣지 않는다.
2. **풀 점검 통과**(아래 ②) — 0점이 섞인 풀에서 뽑지 않는다.
3. **다양성 최소 규칙** — 2점 후보 안에서만 맞춘다. 2점끼리로 못 맞추면 규칙을 포기하고 `note`에 "다양성 최소 규칙 미충족 — 적합 후보 부족"을 쓴다.
4. **구조형 쏠림 감사**(6단계 선발 감사) — n≤3에선 기록만 한다. 이걸 맞추려고 사람을 바꾸지 마라.

첫 무맥락 실행(2026-10-19)에서 다양성 규칙이 정의돼 있지 않자 실행자가 "연령대 1명씩·성별 혼합"을 스스로 정했고, 이어 학력·가구 3/3 쏠림 🔴를 피하려 사람을 세 번 바꾸다 점수 17위까지 내려갔다. 3명 × 필드 10개면 아무렇게나 뽑아도 어딘가는 3/3이 된다 — 그걸 다 피하려 하면 적합한 사람이 밀려난다.

**다양성 최소 규칙 — 이 둘만 본다** (`selection.diversity_check(chosen_rows, pool_rows, n_bands_selected)`):
- **성별**: N명 전원 같은 성별이면 안 된다 — 단 풀에서 그 성별이 75% 이상이면 정상(풀이 원래 그렇다).
- **연령대**: 사용자가 게이트 B에서 연령대를 2개 이상 골랐는데 N명 전원 한 연령대면 안 된다 — 같은 75% 예외.
학력·가구·주거·지역·직업은 다양성 규칙에 넣지 않는다. 그 필드의 쏠림은 감사 파일에 기록될 뿐이다.

**선발도 기록한다 — 합성만 엄격하고 선발은 규율 밖이면 출발점에 구멍이 있는 것이다.** 과거 산출엔 "후보 85명" 중 왜 이 3명인지가 어디에도 없었다. 그러면 ① 같은 브리프를 다시 돌려 다른 3명이 나와도 비교할 근거가 없고 ② "이 사람은 왜 뽑혔어요?"에 "세그 조건에 맞아서"(85명이 다 맞는데)밖에 못 답하고 ③ 세그 3명이 비슷할 때 데이터 탓인지 점수식 탓인지 가를 수 없다. 점수식은 계속 판단으로 짜되, **세그마다 `scripts/selection.py`로 남긴다**:

```python
from selection import log_selection, save_log, audit_selection, write_audit_md, has_red
rec = log_selection(seg="<세그명>", pool=후보행리스트, scores={uuid: 점수}, chosen=[선발 uuid 순서대로],
                    formula={"설명": "<한 줄>", "keywords": {컬럼: {키워드: 가중치}}, "big5": {특성: 가중치}},
                    hard_filter={"sex": "여자", "age": "19-29", ...},   # 세그 정의에 쓴 필드 — 감사에서 제외됨
                    rg_used=used, scanned=scanned, note="<점수 밖 판단이 있었으면 그 사유>")
recs.append(rec)
```
기록되는 것: 점수식 · 후보 전원의 점수·순위·선발 여부 · 읽은 rg와 스캔 행 수 · 점수 분포(최고점 동점자 수, 상위 10) · **세그 적합 인용**.

**선발된 인물마다 세그 적합 인용을 적는다 — `fit_quotes={uuid: "원문 한 문장(교집합 세그는 두 문장을 ` / `로)"}`, `criterion="<게이트 A의 판별 기준>"`.** 하드 필터를 통과했다는 것과 판별 기준을 충족한다는 것은 다르다. 뽑힌 사람의 서술형을 직접 읽고 **그 세그의 판별 기준(행동)을 보이는 문장 하나**를 그대로 옮긴다. 하드 필터 키워드의 문맥이 오탐이거나(BEREX 실전: '신제품'이 빵집 신제품을 잡아 수면×기기 세그에 69세 주부가 들어옴) 기준을 보이는 문장이 없으면 **그 사람은 세그에 안 맞는다 — 다음 순위로 교체**한다. `audit_selection`이 인용 없는 선발을 🔴로 막는다. 이 단계의 품질은 "사람 같은가"가 아니라 **"이 세그에 들어갈 만한 사람인가"**다 — 사람 같은지는 2차 합성 뒤에나 볼 수 있다. 인용은 `selection_log.json`·`selection_audit.md`(부속)에만 실린다. 카드·json·xlsx는 바뀌지 않는다. **점수 정수 동점이 상위 N을 넘으면** 그 안에서 누가 뽑히는지는 uuid 순이다 — 위 '스코어 천장' 그대로, 확장이 아니라 점수식에 변별 항(t점수 같은 연속값)을 넣어라. 상위 N 밖의 인물을 판단으로 넣었다면 `note`에 이유를 쓴다 — 기록된 점수식과 실제 선발이 어긋나면 기록이 거짓이 된다.

**컬럼은 51개 전부 읽어라.** 20개만 읽으면 인물이 반쪽이 되고, `panel.json`에 실을 게 없어 FGD에서 배경 없이 답하게 된다. 특히 **서술형 13개가 이 데이터의 진짜 값어치**다 — 여기에 그 사람의 삶이 통째로 들어 있다. 파일 하나 더 읽는 비용은 몇 초지만, 안 읽으면 있는 사실을 추측으로 때우게 된다.

- **구조형**: `uuid, last_name, first_name, age, sex, region, district, occupation, education_level, bachelors_field, economic_activity_status, income_bracket, family_type, housing_type, housing_tenure(자가/전월세 — 구매력 신호), military_status`

**함정 — `income_bracket`은 개인 소득이지 가구 소득이 아니다.** 전업주부는 `occupation`=무직, `income_bracket`=해당없음으로 나온다. 이걸 그대로 구매력으로 쓰면 **가전·생활재의 실제 구매 결정자를 통째로 버린다**(비데 브리프에서 실제로 그럴 뻔했다). 가구 단위 구매재를 다룰 땐 **가구 구매력 프록시**를 쓴다: 개인소득 + (개인소득 없음 & `family_type`에 배우자 있으면 가구소득 추정 보정) + `housing_tenure` 자가. 점수식에 넣을 땐 기본값으로 **개인소득 450만+ = +1 / (개인소득 해당없음·무직 & 배우자 있음) = +0.5 / 자가 = +0.5**를 쓴다(소득 주축·자가 보조). 다르게 쓰면 `formula`에 적는다. 반대로 `housing_tenure`를 소득보다 무겁게 잡으면 고소득 전·월세 임원이 "구매력 중"으로 떨어지니, **소득을 주축, 자가를 보조**로 둔다.

설치재(비데·정수기·매트리스 등)는 `housing_tenure`가 특히 중요하다 — **자가는 설치 자유, 전·월세는 집주인·이사 제약**이라 이게 곧 결정권 축이 된다.
- **건강·생활**: `bmi_status, waist_status, blood_pressure_status, blood_sugar_status, smoking_status, drinking_status`
- **성격(Big5)**: `openness, conscientiousness, extraversion, agreeableness, neuroticism` — JSON이며 **`t_score`(연속값)와 `description`까지 쓴다.** 라벨만 쓰면 t=25와 t=39가 똑같이 "낮음"이 되어 개인차가 뭉개진다.
- **서술형(반드시)**: `detailed_persona`(가장 풍부 — 그 사람의 삶 전체), `finance_persona`(돈 태도 — 가격 저항·렌탈 수용·소비 우선순위가 통째로), `healthcare_persona`(건강·수면 서사), `professional_persona, sports_persona, arts_persona, travel_persona, culinary_persona, family_persona`, `cultural_background`, `career_goals_and_ambitions`, `skills_and_expertise(_list)`, `hobbies_and_interests(_list)`, `persona`

(예전엔 `marital_status`가 "디코딩 불안정"이라 `family_type`으로 대체하라고 적혀 있었는데, **리더 버그를 고친 뒤 재검증하니 멀쩡하다** — 20대 2,012명에서 null 0건·미혼/배우자있음/이혼/사별 4값. 낡은 제약이 규칙으로 굳어 있었다. `military_status`도 마찬가지다(비현역/현역) — **20대 남성 브리프에선 군 복무가 '가용 시간'을 통째로 바꾸니 놓치면 안 된다.**)

### 6단계 · 주제 맞춤 합성 + 산출
**축 설계 — 기본 세트는 자동, 추천 축만 제시한다.**

축을 머리로 떠올리는 방식은 반드시 빠뜨린다(실제로 초기 실행에서 RFP에 대문짝만하게 쓰인 "레트로 헷징"을 세 판본 내리 놓쳤다). 그래서 절차로 만든다. 단 **기본 축까지 매번 컨펌받는 건 사용자 시간 낭비다** — 기본은 그냥 만들고, 브리프 고유 축만 보여준다.

**변별력 사전 점검 — 코호트 보편값은 축이 될 수 없다.**

축을 확정하기 전에 자문한다: **"이 값이 이 코호트에서 사실상 보편인가?"** (20대의 유튜브, 직장인의 카톡, 전 연령의 스마트폰 보유.) 코호트 최빈값이 ~70%를 넘을 것 같으면 **그 층위는 축이 아니다.**

네이버 실행에서 콘텐츠 채널이 89% 도장으로 반려됐다. 원인은 규칙이 개인을 안 본 게 아니라 **그 층위에 볼 개인차가 없었던 것**이다 — 20대는 다 유튜브를 본다. 이 경우 사후 감사의 처방("임계값을 조정해 분기를 만든다")은 **오진**이다. 임계값을 아무리 만져도 전원이 유튜브를 보는 코호트에서 채널 축은 안 갈라진다.

**답은 축의 층위를 한 단계 내리는 것이다:**
- '어느 채널' → **'그 채널에서 무엇을'**(유튜브(리뷰영상) vs 유튜브(게임공략))
- '쓰냐 안 쓰냐' → **'어떻게 / 얼마나 / 무엇에'**

축의 자격은 "패널 안에서 갈라질 수 있는가"다. 이 함정은 **기본 축 5번(콘텐츠 채널)**에 특히 잘 걸린다.

**기본 축 — 컨펌은 안 받되, 반드시 목록으로 보여준다.**

보여주지 않으면 사용자는 내가 뭘 만드는지 모르고, **빠진 축을 지적할 기회 자체가 사라진다**("기본 축은 자동으로 넣습니다" 한 줄로 넘어가면 눈 감고 승인하는 셈이다). 그러니 **추천 축을 제시할 때 기본 축 목록을 먼저 보여준다.** 그냥 나열하지 말고 **이 브리프에서 각 축이 어떤 값으로 증류될지**를 한 줄씩 붙인다 — 그래야 "아 그건 이렇게 잡는구나"를 보고 그 자리에서 고칠 수 있다("거기에 X도 넣어"). 컨펌은 기다리지 않고, 이의가 없으면 그대로 간다.

제시 예 (비데 브리프):

| 기본 축 | 이 브리프에선 이렇게 잡힌다 |
|---|---|
| 기본 프로필 + Big5 5종(t) | 직업·가구·**자가 여부(설치재 결정권)**·소득 / 친화(동조·반박)·신경성(방어) |
| 토픽 몰입 `[Q+INF]` | 위생·에티켓 감수성 — 정돈·강박 텍스트 → 냄새 민감도·화장실 공유 스트레스 |
| 카테고리 관여 `[Q+INF]` | 욕실·인테리어 관여 — 인테리어·소품 텍스트 → 욕실 확장 관심 |
| 지출 여력 `[Q]` | 렌탈(월 3.4만) vs 일시불(51.9만) 수용 — finance_persona 증류 |
| 콘텐츠 채널 `[INF]` | 드라마타이즈 광고를 어디서 만나나 |
| 바이럴 `[INF]` | 오가닉 확산 가능성 |
| 모순 `[Q-derived]` | 자극물 앞에서 흔들릴 지점 |
| 브랜드 선호 | 미부여 `[가설]` |

**기본 축 (묻지 않고 자동 — 단 위처럼 보여준다)** — 어느 브리프든 공통:
1. **기본 프로필** — 직업·학력·가구·주거·소득 + **Big5 5종 전부(t점수)**. 특히 **친화성**(그룹에서 동조하나 반박하나)과 **신경성**(자극물에 방어적인가)은 **FGD 역학을 결정**하니 절대 빠뜨리지 않는다. 개방·외향만 쓰면 좌담회 행동을 못 읽는다.
2. **토픽 몰입** — `[Q확인]` + `[INF확장]`
3. **카테고리 관여** — `[Q확인]` + `[INF확장]`
4. **지출 여력** — `finance_persona` 증류 `[Q]`
5. **콘텐츠 채널** — `[INF]` (이 캠페인을 어디서 만나나 — IMC 설계에 필수)
6. **바이럴·공유 성향** — `[INF]`
7. **모순** — `[Q-derived]`
8. **브랜드 선호** — `[가설]` 미부여
9. **상식 기저** — `[T]` (아래 'FGD 신빙성 4종' (1))
10. **FGD 화법** — `[Q-derived]` (아래 'FGD 신빙성 4종' (2))

**추천 축 (브리프에서 도출해 목록으로 제시)** — 브리프의 **과제·자극물·평가지표·주의사항 문장**을 훑어 그 캠페인 고유의 축을 뽑는다. **브리프 문장에서 기계적으로 뽑아라.** 목록을 보여주고 사용자가 고르거나 통과시킨다(가벼운 게이트).

도출 예 (PUBG×IVE RFP):
- *"과거 컨셉 활용 시 신곡 대비 옛날 느낌 헷징 전략 필요"* → **레거시/레트로 감수성**
- *"PUBG IDOL 런칭(K/DA 구조)"* → **오리지널 IP 수용성**
- *"United 무대에서 퍼포먼스 최초 공개"* → **이스포츠 관람 의향**
- *"인게임 스킨·이모트 출시"* → **인게임 결제 경험**(지출 여력과 다른 축이다 — 돈이 있어도 게임 내 과금은 안 할 수 있다)

**`[역발상]` 세그가 확정됐으면 축도 따라간다** — 역발상 세그의 존재 이유(브리프 전제가 깨지는 지점)를 관찰할 수 있는 **대비 축**을 1개 이상 넣는다. 예: '알면서도 안 사는 층' 세그면 → "구매 보류의 실제 이유" 축(브리프의 전제 장벽 vs 카드에서 발견한 다른 장벽). 이 축이 없으면 역발상 세그를 뽑아 놓고 FGD에서 정방향과 같은 질문만 하게 된다.

**읽기 범위 ≠ 표시 범위.** 컬럼은 전부 읽되, 카드에는 **그 FGD 토픽에 필요한 축만 증류해서** 올린다. **원문 덤프는 카드가 아니다** — 게임 콜라보 좌담회에 `healthcare_persona` 원문을 통째로 붙이면 정보가 아니라 소음이고, 읽는 사람이 뭘 봐야 할지 모른다. 서술형은 **읽어서 판단 재료로 쓰고**, 카드엔 **토픽 축으로 증류한 값 + 근거 인용 한 조각**만 남긴다.

예: PUBG×IVE 좌담회라면 `finance_persona`를 통째로 붙이는 게 아니라 → **"굿즈·스킨 지출 여력: 하 (월 80만·저축은 부모 의존)"** 로 증류한다. 같은 필드라도 매트리스 좌담회에선 **"렌탈 월정액 수용도"** 로 증류된다. **필드는 하나인데 토픽마다 다른 축이 뽑힌다.**

**INF를 0으로 만드는 게 목표가 아니다.** 데이터에 그 축이 있으면 `Q`, **없으면 `INF`로 합성한다.** 캠페인이 요구하는 축 중 니모트론에 아예 없는 것(예: 바이럴 성향, 콘텐츠 채널 선호, 카테고리 관여도)은 **반드시 합성해야** 한다 — 안 하면 그 좌담회를 못 돌린다. 달라지는 건 **합성의 토대**다: 취미 리스트 하나로 짐작하던 걸 이제 `finance/healthcare/detailed` 등 서술형 전체 위에서 합성하니 근거가 훨씬 두껍다. 목표는 INF를 없애는 게 아니라 **꼭 필요한 축에만, 더 두꺼운 Q 위에서** 쓰는 것이다.

**합성하기 전에 — `Q`에 이미 있는지부터 확인한다.** 추측은 최후 수단이지 기본값이 아니다.

**그러나 `Q`는 그 축의 앵커이지 전부가 아니다 — 카드의 침묵은 부재가 아니다.** 서술형은 그 사람 삶의 **표본**이지 목록이 아니다. 카드에 "코인 노래방에서 아이돌 노래를 부른다"가 있다고 해서 그가 스밍·굿즈·콘서트를 안 한다는 뜻이 아니다. 카드가 그 얘길 안 했을 뿐이다. Q에서 멈추면 그 사람은 노래방밖에 모르는 납작한 인물이 된다.

그러니 **Q로 축이 확인되면, 그 축의 나머지 모양을 `INF`로 채운다.** 근거는 카드의 **다른 필드를 교차**해서 만든다(finance·성격 t점수·다른 도메인 서술). 한 축에 Q와 INF가 **같이** 올라간다.

예시 — 팬덤 몰입 축:
- `[Q]` 코인 노래방 열창 ← 원문 인용
- `[INF]` 음원 스밍 **중**(음악 감상 신호) · 굿즈·포토카드 **하**(finance: 알뜰·전세 저축 지향) · 콘서트 직관 **중**(외향 51) · 팬 커뮤니티 활동 **하**(커뮤니티 신호 없음)

이렇게 해야 자극물 앞에서 **어디가 열리고 어디가 막히는지** 보인다. "노래방"만 있으면 인게임 굿즈를 팔 수 있는지 없는지 답이 안 나온다.

**단, 축 자체를 INF로 창조하지는 않는다.** 카드에 아이돌 신호가 전혀 없는 사람을 INF로 팬으로 만들면 규칙 4 위반이다. 차이는 명확하다 — **있는 축을 넓히는 건 확장, 없는 축을 만드는 건 날조.** 그리고 INF 확장은 Q와 **모순되면 안 된다**(원문이 "굿즈를 안 산다"면 굿즈 INF는 '하'로 고정).

실제로 이 스킬 초기 실행에서 이런 실수가 있었다: 숙면 노력도를 취미·혈당으로 **추측**했는데 `healthcare_persona`에 *"침대에 누워 스마트폰 보는 시간이 길어지며"* 라는 실제 수면 서사가 있었고, 렌탈 수용성·가격 저항을 `income_bracket`으로 **추측**했는데 `finance_persona`에 *"저축은 부모님 의존, 통장 바닥나면 용돈 부탁"* 이라는 돈 태도가 통째로 있었다. **사실이 있는데 추측을 쓰면 근거를 스스로 얇게 만드는 것**이다. 규율을 어긴 건 아니지만, 이 도구의 값어치를 스스로 깎는다.

그러니 순서는: ① 서술형 필드에서 그 축이 이미 서술돼 있나 찾는다 → 있으면 `Q`(원문 인용) 또는 `Q-derived`(원문에서 연역). ② 없을 때만 `INF`로 추측한다. **INF 개수가 적을수록 좋은 패널이다.**

**모순을 캐라 — 이미 카드에 써 있다.** `detailed_persona`엔 *"비만 체형에 고민이 있지만 쉽게 움직이지 못하는 모순"*, *"부모님과 사는 안정적인 삶에 안주하면서도 경제적 자립을 원한다"* 처럼 **내부 긴장이 명시**돼 있는 경우가 많다. 도메인 교차에서도 나온다(`finance_persona`는 "저축 못 함"인데 `culinary_persona`는 "주 5회 외식"). 대조 표지(`~지만`, `하면서도`, `정작`, `그러나`, `반면`, `모순`)를 단서로 찾아 **카드에 '모순' 항목으로 넣는다.**

왜 중요하냐면 — **사람을 살아있게 만드는 건 일관성이 아니라 긴장이다.** 매끄럽게 정합적인 페르소나는 가짜 티가 나고 FGD에서 뻔한 말만 한다. 모순이 있어야 자극물 앞에서 흔들리고, 그 흔들림이 우리가 찾는 균열 지점이다.

선발된 실제 인물 위에 토픽 관련 속성을 층으로 합성하고, **모든 값에 provenance 태그**를 단다:

- 카드 신호에서 연역 → `Q-derived` (예: 관여도 상/중/하)
- 외부 분포 배정 → `T` (예: 폰 브랜드·미디어 이용률을 연령 분포로 확률 배정)
- 성향 추론(합성) → `INF` (미디어 습관·숙면 노력도 등)
- 브랜드 선호·특정 피처 관심 → `가설` (findings 아님, FGD 자극물로 압박 테스트할 대상)
- 원본 필드 그대로 → `Q`

**INF 합성 원칙 — 이걸 어기면 패널이 죽는다**

합성 속성은 반드시 **개인마다 서로 다른 실제 신호에서 파생**해야 한다. 세그 단위로 같은 문구를 찍어내는 "도장"은 금지다. 왜 중요하냐면 — 세그 상수를 박는 순간 개인은 사라지고 세그 라벨만 남는다. 그러면 FGD에서 같은 세그 3명이 똑같은 말을 하고, 우리가 보존하려던 '규율 있는 분기'가 통째로 증발한다. 그건 패널이 아니라 라벨 3장이다.

구체적으로:
- 각 INF는 그 사람의 취미·직업·건강·성격·연령 등 **개인 필드에서 계산**한다(키워드 매칭 + 규칙).
- 각 INF 값에 **근거 신호를 괄호로 병기**한다. 예: `AI 관심: 상 (개방성 매우 높음, '게임')`, `노트북 용도: 사진·영상 편집 + 과제 (영상, 사진)`. 근거를 보이면 개인차가 드러나고, 매칭 노이즈도 감사할 수 있다.
- 세그는 **어떤 축을 합성할지**만 정하고(예: 매트리스=숙면 노력도, 노트북=주용도·AI 관심), **값은 개인에서** 나온다.
- 같은 세그 안에서 값이 전부 같게 나온다면 규칙이 개인 신호를 안 보고 있다는 뜻이니 규칙을 고친다.

**분기 자가진단 — 산출 전에 반드시 측정한다.**

위 원칙은 이미 있었지만 **측정 기준이 없으면 눈으로 놓친다.** 실제로 WRTN 실행에서 '광고 각인'이 7/9 한 값에 쏠린 걸 못 보고 산출했다. 사람 눈은 쏠림에 관대하다. 그러니 **산출 직전 `scripts/axis_audit.py`로 축별 최빈값 점유율을 센다.** (도장이 남아 있으면 종료코드 1을 뱉는다 — 파이프라인에서 산출을 막아라.)

| 최빈값 점유율 | 판정 | 조치 |
|---|---|---|
| ≥78% | 🔴 도장 | **고치기 전엔 산출하지 않는다** |
| 56~77% | 🟡 쏠림 | 임계값을 조정한다. **단, 값이 코호트 보편이면 임계 조정으론 절대 안 갈라진다 — 축의 층위를 내려라**(위 '변별력 사전 점검') |
| ≤55% | 🟢 정상 | 통과 |

**점유율은 표시되는 정수 %로 판정한다.** 7/9 = 77.78%다. 화면엔 '78%'로 찍히는데 `share >= 0.78`은 False라, **이 도구를 만들게 한 바로 그 WRTN 사건이 도장이 아니라 쏠림으로 통과했다.** 5/9 = 55.56%('56%'로 표시)도 정상으로 샜다. 세그당 3명·패널 9명이면 점유율이 11%씩 계단이라 **항상 경계에서 터진다.** 표시와 판정이 어긋나면 도구를 믿을 수 없다.

**세그별로도 재라 — 전체만 재면 원조 실패를 못 본다.** 이 스킬의 원조 실패는 "세그당 3명이 똑같음"이다. 그런데 세그A 전원 '상' / B 전원 '중' / C 전원 '하'면 **패널 전체 최빈값은 33%로 정상 통과**한다 — 세그 간 차이가 세그 내 도장을 완벽히 가린다. `axis_audit.py`는 `세그` 컬럼이 있으면 세그별 감사를 자동으로 돌린다.

**우연과 고장을 가르는 법.** n=3에서 3수준 축이 3/3으로 뭉칠 확률은 약 11%다 — 축 13개 × 세그 3개면 **우연만으로도 4건쯤 뜬다.** 그러니 건수를 세지 말고 **같은 축이 여러 세그에서 반복 도장인지**를 봐라. 반복이면 규칙이 개인을 안 보는 것(확실). 단일 세그면 우연이거나 동어반복이다.

**예외 셋 — 도장이 아니다:**
1. **의도적 고정값·설계상 공통 행** — 브랜드 선호=미부여, 상식 기저(코호트 공통), 기본 프로필·Big5·FGD 화법(축이 아님). `axis_audit.py`가 이 행들을 기본으로 뺀다(헤더 앞부분 일치 — 괄호 설명이 붙어도 빠진다).
2. **세그 정의를 되풀이하는 동어반복 축** — 예: "AI 신호 없는 사람"만 뽑은 세그의 "AI 접점=전무", 최저가 신호로 뽑은 '가격 사냥꾼'의 "탐색의 효용=놀이". **애초에 카드에 올리지 마라** — 정보량이 0이고 자리만 차지한다.
3. **사용자가 게이트 B에서 정량 예고를 받고 감수하기로 확정한 쏠림** — 예: 단일 연령대 선택 → 인지 경계 쏠림. 도장이 아니라 **'기록된 트레이드오프'**다. `--accepted "<축이름>"`으로 표시하고 산출물에 수치와 함께 명시한다.

**인지 경계도 개인화한다 — 균일한 경계는 경계가 아니다.**

> **여기서 만드는 건 경계의 '기질(基質)'이다 — 구체 경계가 아니다.** 이 구분을 놓치면 카드 안정성 규칙(핸드오프 섹션)과 충돌한다. 여기선 **디지털 접점 수·개방성·IT 신호처럼 잘 안 변하는 신호로 '경계 단계'만 배정**한다. **특정 도구·인물·유행어**에 대한 구체 경계("이 사람은 Copilot을 알 만하다")는 **카드에 박지 않고**, FGD 시점에 `references/topic_grounding.md` 절차로 이 기질 위에 얹는다. 그래야 같은 패널로 여러 FGD를 돌릴 수 있고, 7월에 만든 카드가 11월에 낡지 않는다.

`[경계:모름]`은 이 스킬의 핵심 산출인데, **전원에게 같은 경계를 주면 9명이 다 "그게 뭔데요"만 하고 좌담회가 안 굴러간다**(WRTN에서 실제로 9/9 동일하게 나왔다). 경계도 INF 원칙을 그대로 따른다 — **개인 신호에서 파생해 단계로 나눈다.**

**단계 문구는 카테고리의 대중 노출도에 맞춘다.** 아래 예는 AI 도구처럼 신흥·희소 대상용이다. 전국 TV광고가 나간 카테고리(매트리스·정수기 등)에서 "이름도 못 들어봄"은 비현실적이다 — 그땐 단계를 **"이름만(광고로) / 기본 기능까지 / 신기능(앱·센서 등)까지"**처럼 노출도 위에서 다시 나눈다. 기질 신호(아래 디지털 접점 수·개방성)는 그대로 쓴다.

**디지털 접점 수 = 그 사람 텍스트(취미 목록 + 서술형)에 나오는 서로 다른 디지털 채널 종류 수.** 채널: 유튜브 · SNS(인스타·페이스북·틱톡 등) · 온라인 커뮤니티·카페 · 메신저 단톡 · OTT · 온라인 쇼핑·라이브커머스 · 앱(가계부·배달·운동 등 용도 앱) · 게임 · 팟캐스트·오디오 · 웹툰·웹소설 · 블로그 · IT 기기 리뷰. 같은 채널이 여러 번 나와도 1개로 센다.

예 (AI 도구 좌담회):

| 단계 | 개인 신호 근거 |
|---|---|
| 이름도 못 들어봄 | 디지털 접점 0~1개 · 개방성 낮음 |
| 들어는 봤는데 뭔지 모름 | 디지털 접점 2~4개 · 유튜브·뉴스 노출 |
| 대충 아는데 안 써봄 | 디지털 접점 5개+ · 커뮤니티·IT 신호 |

같은 20대여도 **디지털 접점 7개인 사람과 0개인 사람은 경계가 달라야 한다.** 그 차이가 좌담회의 분기를 만든다 — 한 명은 "챗지피티 같은 건가요?"라고 묻고 다른 한 명은 "그게 뭔데요"라고 멈춘다.

**FGD 신빙성 4종 — 이게 안 실리면 패널이 좌담회에서 이상한 소리를 한다.**

실행에서 반복된 실패 유형: FGD 발화가 상식에 어긋난다 — 20대 직장인이 배달앱을 모른다고 하고, 월 소득 대비 터무니없는 지출을 아무렇지 않게 수용하고, 어색한 번역투로 말한다. 원인은 FGD 스킬이 아니라 **panel.json에 네 가지가 안 실려서**다. FGD는 카드에 있는 것만 근거로 말할 수 있으니, 카드가 침묵하면 모델이 즉석에서 메우거나(유창함=오염) "모르겠다"를 남발한다(상식 위반). 넷 다 **이쪽에서 실어 보낸다** — 전부 기존 `rows` 구조에 행으로 실리므로 스크립트 수정이 필요 없다.

**(1) 상식 기저 — 카드의 침묵을 '모름'으로 내보내지 마라.**

'변별력 사전 점검'의 거울상이다: **코호트 보편값(~70%+)은 축이 될 수 없고, 동시에 '모름'도 될 수 없다 — 그건 상식이다.** `[경계:모름]`은 신흥·희소·전문 대상 전용이다(AI 신도구·인게임 결제 구조·니치 브랜드). 카톡·유튜브·배달앱·쿠팡·물가 감각·대중 브랜드처럼 그 코호트가 당연히 아는 것은 카드에 신호가 없어도 "모름"이 아니라 **기본 보유**다.

**이 단계의 상식 기저는 잠정값이다 — 근거는 2차 합성이 채운다.** 패널은 행의 자리와 하한선 역할만 확보하고, 사람별·연령대별 근거(공공 통계 이용률·출처·연도)는 2차 합성(persona-secondary-fusion / persona-quant-match-fusion)이 `fused.common_ground`로 다시 만든다. 그 융합층이 있으면 FGD는 이 행 대신 그걸 하한선으로 쓴다. 그래도 2차 합성 없이 `panel.json`이 바로 FGD로 갈 수 있으니 잠정값도 아무렇게나 쓰지 않는다:
- **연령대별로 다르게 쓴다.** 같은 패널의 33세와 67세에게 같은 상식 기저를 깔지 마라(첫 무맥락 실행에서 전원 동일로 나왔다). 그 연령대에 70% 넘게 보편이라고 자신할 수 있는 것만 넣고, 애매하면 뺀다 — 빠진 건 2차 합성이 근거를 찾아 채운다.
- `panel.json`의 `meta`에 `"common_ground": "잠정 — 연령대 추정. 근거는 2차 합성 fused.common_ground에서 교체"`를 적는다(카드·xlsx는 그대로).

방법: 토픽이 속한 생활 도메인의 **코호트 보편 접점·상식 4~6개**를 rows에 한 행으로 싣는다:

`("상식 기저", "배달앱·간편결제 일상 사용 · 쿠팡 로켓배송 인지 · OTT 구독료 감각(월 1~2만)", "T")`

개인 카드가 **명시적으로 반대**하면(디지털 접점 0, 비이용 서사) 그때만 개인 단위로 하향한다. 어떤 대상의 판정 순서: ① 코호트 보편인가? → 상식 기저 ② 카드에 개인 신호가 있나? → Q/Q-derived ③ 둘 다 아니면 → 그때만 경계 후보.

**(2) FGD 화법 — Big5를 화법으로 변환해 실어 보낸다.**

FGD 스킬은 화법 차등(말수·헤지·동조)을 설문 반응습관(ARS/MRS/ERS)에서 가져오는데 니모트론엔 설문이 없다 → 소비 측 폴백으로 **전원 균형형** → 9명이 같은 톤으로 말하고 좌담회가 밋밋해진다. 니모트론엔 대신 Big5 t점수가 있다. 인물마다 변환해 rows에 싣는다:

| Big5 (t점수) | 화법 파라미터 |
|---|---|
| 외향성 | 말수·발언 순서 — t≥60 길게·먼저 나섬 / t≤40 짧게·지명 시만 |
| 친화성 | 동조↔반박 — t≥60 동조·중재 / t≤40 반박·이견 제기 |
| 신경성 | 방어·민감 — t≥60 자극물에 걱정·리스크부터 / t≤40 무덤덤 |
| 개방성 | 근거 밖 확장 자유도 — t≥60 "~일 것 같아요" 헤지 확장 / t≤40 "모르겠다" 컷 |
| 성실성 | 즉답↔신중 — t≥60 조건 달아 따져 답함 / t≤40 즉흥·인상 위주 |

`("FGD 화법", "말수 적음(외향 t38) · 반박형(친화 t35) · 자극물에 방어적(신경성 t63)", "Q-derived")`

t점수가 근거이니 `Q-derived`다. **같은 세그 3명의 화법이 같게 나오면 t점수를 안 본 것이다** — INF 도장 원칙이 여기도 그대로 적용된다.

**(3) 스탠스 방향 — 상/중/하는 발화가 안 된다.**

"관여도 중"으로는 그 사람이 자극물에 끌릴지 저항할지 모른다 — 방향 없는 축은 FGD에서 모델이 방향을 즉석 작화하게 만든다. **FGD 토픽에 직결되는 축(추천 축 전부 + 토픽 몰입·지출 여력)은 강도에 방향을 함께** 증류한다: `끌림 / 저항 / 양가 / 유보` + 근거 인용 한 조각.

`("구독 전환", "저항 — 고정비 늘리기 싫어함 (finance: '월 고정 지출을 최소로 유지')", "Q-derived")`

방향의 근거가 카드에 없으면 만들지 말고 `유보`로 두되, 유보에도 이유를 단다("돈 태도 신호 자체가 없음"). 양가는 모순 항목과 연결하면 가장 좋다 — 그게 자극물 앞에서 흔들릴 지점이다.

**(4) 인용 위생 — 니모트론 원문도 합성문이다.**

서술형 필드는 LLM이 쓴 글이라 번역투·비문·비현실 조합이 섞여 있다. 원문을 통인용해 카드에 박으면 그 어색함이 FGD 발화로 그대로 흘러들어 "사람 같지 않은 말"의 직접 원인이 된다. 규칙:
- **인용은 사실 명제만 추려 요지화한다.** 원문은 raw에 그대로 실리니 손실이 없다. 카드 인용은 짧게, 자연스러운 한국어로.
- **말투는 원문에서 가져오지 않는다.** 말투의 근거는 데모(연령·직업·지역) × FGD 화법 프로파일이다.
- **서술형이 앞뒤가 안 맞는 인물은 교체한다.** 재산·직업·연령이 서로 비정합인 건 '모순 자산'(심리적 긴장 — 보존 대상)이 아니라 **데이터 결함 — 캐리어 교체 사유**다. 긴장은 살리고 결함은 버린다.

**개연성 스모크 테스트 — axis_audit 다음, 산출 직전.**

axis_audit은 분기를 재지만 상식은 못 잰다. 인물별로 셋을 자문하고, 하나라도 걸리면 **고치기 전엔 산출하지 않는다**:
1. **수치 정합** — 소득 × 지출 여력 축 × 주거 × 연령이 서로 말이 되나. 월 80만 대학생의 "지출 여력 상"은 결함이다(단, 카드에 '모순' 항목으로 명시한 긴장은 예외 — 그건 의도된 산출이다).
2. **상식 리허설** — 코호트 보편 질문 2개(예: "배달앱 써보셨어요?", "이 광고 어디서 보셨을 것 같아요?")에 이 카드만으로 상식적인 답이 나오나. "모른다"가 나오면 상식 기저 행이 누락된 것이다.
3. **인용 위생** — rows의 인용 중 통인용·번역투·비문이 남았나.

**선발 감사 — axis_audit 다음, 같은 자리에서.** axis_audit는 합성 축의 쏠림을 재지만 **선발의 쏠림**은 못 잰다(같은 키워드에 높은 점수를 주면 그 키워드를 가진 비슷한 사람만 올라오는데, 그건 축이 아니라 사람이다). 5단계에서 쌓은 `recs`로 잰다:

```python
save_log(recs, "<outputs>/selection_log.json")
flags = audit_selection(recs, accepted=["<게이트 B에서 감수 확정한 필드>"])
write_audit_md(recs, flags, "<outputs>/selection_audit.md")
if has_red(flags): ...   # 🔴(적합 인용 없음·풀 점검 실패·전원 동점)면 원인을 고치기 전엔 산출하지 않는다
```
재는 것: 세그 정의(하드 필터)에 안 쓴 구조형 필드(지역·소득·직업·학력·가구·주거·경활·혼인·연령)마다 **[후보 풀 비율] vs [선발 N명 비율]**. 풀이 원래 그렇게 생겼으면 선발이 그런 건 정상이고(🟢), **풀에 없던 집중**이면 표시한다(선발 점유 ≥78% 이고 풀보다 30%p 이상 높음). **세그당 3명 이하면 이 표시는 🔴가 아니라 🟡(기록)다** — 선발 우선순위 4번. 🔴로 산출을 막는 건 셋뿐이다: **적합 인용 없음 · 풀 점검 실패(0점 >15%이거나 다른 풀에서 잼) · 선발 전원 동점.** 세그 간 같은 필드가 반복 🟡이고 **그 필드가 점수식에 들어 있으면** 점수식을 고친다(가점이 그 집단을 끌어올리고 있다). 점수식에 없는 필드의 반복은 풀 구조라 기록만 한다. 판정은 표시 정수 %. n=3에서 한 세그의 2/3 쏠림은 우연일 수 있으니(약 11%) 건수가 아니라 **같은 필드가 여러 세그에서 반복되는지**를 본다 — 감사 파일 끝에 자동으로 모아 준다. 동점 선발·순위 밖 선발도 여기서 잡힌다.

**이 두 파일은 부속이다.** `panel.html` · `panel.json` · `panel_carriers.xlsx`의 형식과 내용은 **바뀌지 않는다** — 선발 근거는 그 셋에 섞지 않고 `selection_log.json`(기계용) · `selection_audit.md`(사람용)에 따로 둔다. 전달할 땐 패널 산출 3종을 먼저, 부속 2종은 "선발 기록"으로 구분해 붙인다.

그 다음 `scripts/render.py`로 **산출 3종**:
```python
sys.path.insert(0,"nemotron-data/skill_scripts")
from render import render_panel, save_xlsx, save_panel_json
render_panel(panel_dict, "<outputs>/panel.html")      # 사람이 보는 카드 (증류본)
save_xlsx(records,      "<outputs>/panel_carriers.xlsx")  # 검증·핸드오프 표
save_panel_json(panel_dict, "<outputs>/panel.json")   # FGD 입력 (원본 전부 + 합성 전부)
```
형식은 `render.py` 상단 docstring 참조. **이 스킬에선 여기서 저장·전달하지 않는다** — 감사까지 마친 뒤 게이트 C에서 승인받고 저장하며, 전달은 `최종 전달`에서 2차 합성 산출과 함께 한다.

**보여주는 것 ≠ 넘기는 것 — 그래서 JSON이 따로 있다.**

카드는 증류본이다. 게임 콜라보 좌담회에 `healthcare_persona` 원문을 붙이면 소음이니 토픽 축만 올린다. **그런데 FGD에서 그 사람이 자기처럼 말하려면 카드에 안 올린 배경(직업 서사·돈 태도·건강·취미 리스트)까지 근거가 되어야 한다.** 카드를 소음으로 채우지 않으면서 근거는 다 넘기는 유일한 길이 **분리**다:

| 산출 | 담는 것 | 소비자 |
|---|---|---|
| `panel.html` | 토픽 축만 **증류** | 사람 |
| `panel_carriers.xlsx` | 축 + 근거 + 데모 | 검증·대조 |
| **`panel.json`** | **니모트론 원본 51컬럼 전부 + 합성 축 전부** | `persona-qual-fgd` · `nemotron-fgd-studio.html` |

그러니 5단계에서 **컬럼은 51개 전부 읽어라**(`ALL51`). 카드에 안 쓸 컬럼도 JSON엔 실린다 — 그게 다음 FGD의 근거다.

**JSON 계약** (소비 측 `loadPanel`/`normPerson`/`nemoRoster`에서 확인된 것):
```
{meta:{brand,category,…},
 segments:[{name,color,criteria,personas:[
   {uuid, header, name, cell,
    rows:[[라벨,값,태그], …],        ← 합성 축. 태그는 3번째 원소
    contradiction, boundary,          ← 카드의 '모순'·'인지 경계'를 별도 필드로
    raw:{…원본 51컬럼…, big5:{개방성:"t49 · 보통", …}}}]}]}
```
`save_panel_json`은 `panel_dict`의 `people[]`에서 `raw`·`contradiction`·`boundary`·`name`을 추가로 읽는다(**`render_panel`은 이 넷을 무시하므로 HTML 산출은 그대로다**). Big5 5컬럼은 JSON 문자열이라 `raw.big5` 한 덩이로 접어준다 — 안 접으면 프롬프트에 원시 JSON이 통째로 박힌다. **'상식 기저'·'FGD 화법'·스탠스 방향은 별도 필드가 아니라 rows의 행이다** — 그래서 소비 측 수정 없이 그대로 전달된다.

### 게이트 C · 패널 승인 `[게이트 C]` — 이름표만 보여준다
6단계 축 행·감사가 끝났으면 **산출 전에 멈추고 승인을 받는다.** 그 전에 이름표 두 개를 만든다:
- **세그 정의(`title`)** — 세그를 5~8단어로 부르는 이름(예: "돌아올 마음 남은 옛 단골"). `persona-qual-fgd`는 세그 이름으로 이 `title`을 쓴다. `subtitle` = `<세그명> · <판별 기준> · <연령>`.
- **페르소나 정의(`title`)** — 사람마다 한 줄(예: "혼자 있을 곳을 찾아 카페를 옮긴 간편식파 취준생"). **모든 주장이 니모트론 원본으로 확인돼야 한다** — 브랜드 이동("투썸으로 옮긴")·구매 이력처럼 데이터에 없는 것은 넣지 않는다(그건 7단계 [가설]의 일).

승인 화면에는 **세그 정의와 사람 정의만** 보여준다 — 데이터·행·점수·표를 붙이지 않는다. 세그마다 이 형식 그대로:
```
**<세그 정의>**
<세그명> · <판별 기준>

- **<페르소나 정의>**
  <이름> <나이><성> <지역> <직업>
```
그다음 `AskUserQuestion` 한 번 — **패널 승인**: "승인 — 2차 합성 진행 (Recommended)" / "일부 교체" / "세그 다시 구성". "일부 교체"면 누구를 왜 바꿀지 받아 같은 세그 후보 풀의 다음 적합자로 교체하고(`note`에 사유) **바뀐 세그만 다시 보여주고 다시 묻는다.** "세그 다시 구성"이면 게이트 A로. 승인 전에는 1차 산출도 2차 합성도 하지 않는다.

승인되면 6단계 산출 3종 + 선발 기록 2종을 저장하고, **곧바로 이름표를 panel.json에 찍는다**(`save_panel_json`은 title을 버린다):
```python
import sys; sys.path.insert(0, "nemotron-data/fusion/scripts")
import fusion as fu
# panel_dict["segments"][i]["title"/"subtitle"], panel_dict["segments"][i]["people"][j]["title"] 를 채워 둔 상태
fu.stamp_titles("<out>/panel.json", panel_dict)
```
이 다섯 파일이 **1차 산출**이다. 바로 넘기지 말고 7단계로 이어 간다(마지막에 함께 전달).

### 7단계 · 2차 합성 (승인된 패널만 · 정량 매칭 없음)
`persona-secondary-fusion`의 규율을 따르되 이 스킬의 사정이 다르다:
1. **사실 앵커는 하나뿐이다 — 니모트론 원본 `[Q]`.** 정량(설문) 응답을 붙이지 않는다. 원본에서 계산·유도한 값은 `[Q-derived]`.
2. **원본에 없는 개인 사실은 `[가설]`로 낮춘다** — 브랜드 이력(과거·현재·다음 컴포즈 의향), 커피 장면 중 원본에 없는 부분, SNS 이용 플랫폼(연령대 통계로만 정할 때). 가설은 지우지 않고 **FGD에서 흔들어 볼 대상으로 남긴다** — 그래서 브랜드 전기마다 `fgd_probe`(그 가설을 흔들 질문)를 쓴다.
3. 2차 합성은 **컴포즈 커피 전용 구조**다(커피 장면·브랜드 전기·커피의 의미·커피 밖 소비). 범용화하지 않는다.
4. 2차 자료는 **공개 저장소 `nemotron-data/fusion/`** + 웹서치. Google Drive는 쓰지 않는다.

**입력 수집 — 둘 다 돌린다(스킵 금지).**
- **트렌드 리포트 — `fusion/trends/*.md`** (공개 리포트 요약 24건 — 모집단·표본·조사기간·핵심 수치·사용 규칙). 원본 PDF는 저장소에 없다(발행처 저작물) — 요약의 `원문` URL을 출처로 적는다.
  ```python
  import trends
  lib = trends.load(); print(trends.table(lib))
  for m in trends.find(lib, "카페", "커피", "<세대>", "SNS", axis="소비"):   # 브리프·패널에 맞는 키워드
      print(m["title"], m["ages"], trends.fits_age(m, 27))
  ```
  요약의 **사용 규칙(모집단 밖 적용 금지·분모 조건·제외 수치)을 그대로 지킨다.** `ages` 밖 인물에게 쓰지 않는다(`verify`가 막는다).
- **웹서치 — 4축 모두 새로 검색한다:** ⓐ카테고리(커피 프랜차이즈·저가 커피·컴포즈·경쟁 브랜드·브리프 주제) · ⓑ세대·연령 트렌드(패널 연령대별) · ⓒ소비행태 · ⓓ미디어·콘텐츠 습관. 같은 세션의 이전 검색으로 때우지 않는다. 연령별 수치는 그 연령대 인물에게만.
- **게이트**: 시점·모집단·출처 등급을 통과한 자료만. `fusion/trends/`에 맞는 리포트가 없으면 `meta_fusion["report_gap"]`에 사유를 적고 웹서치를 주 소스로.

**인물마다 저작한다** (`fusion.py` 머리 주석의 `authored` 형식):
- **diary** — 1인칭 7~8줄. 니모트론 생활 서사(직업·동네·가족·취미·돈 태도)를 뼈대로, **트렌드 유래 문장 2줄+**("요즘 내 또래는 ~라던데" 배경체) — 줄 번호를 `diary_trend_lines`에. 컴포즈·커피 이야기는 [가설] 수준으로 가볍게("~하는 편인 것 같다"). 본인 나이는 원본 나이만.
- **trend_context** — 3건+, 4축 중 3축+(`axis`), `[T:리포트]` 1건+(`key` = `fusion/trends/` 파일명) + 출처·시점.
- **sns_use** — 이용 플랫폼 목록 + 근거 태그. 연령대 이용률 통계(`[T:리포트]`/`[T:웹]`)와 원본 서술 단서(`hobbies`·`arts_persona`에 유튜브·인스타 언급 등)로 정한다. 통계만으로 개인을 정하면 `[가설]`. **이 목록이 media_diet·instagram·rising_feed·common_ground의 기준이다.**
- **common_ground** — 원본 나이의 연령대(20대 = 19~29) 기본선(메신저·유튜브·온라인쇼핑·간편결제·배달앱·OTT·SNS·숏폼 등) 이용률을 공공 통계(최신 연도)로 찾아 `보편`(≥70%)/`다수`(50~69%)/`추정`, 50% 미만은 `excluded`. `stat`에 **% 수치 필수**. sns_use에 없는 플랫폼을 보편·다수로 넣으려면 `personal_override`에 처리 근거.
- **media_diet** — sns_use 위에서 구체 채널·콘텐츠 추정('추정' 표시). **sns_use 플랫폼 중 1개+를 이름으로.**
- **instagram** — 가상 계정 프로젝션([INF·추정], 가상 핸들, 실존 계정 연결 금지). sns_use에 인스타그램이 없으면 '계정 없음'·'눈팅 전용'·'비공개 부계' 중 하나. 같은 세그 안 grid·style 중복 금지.
- **life_scenes** — 5영역 중 4+(식생활·여가·취향·일·관계·동네·주거). 원본 필드(`culinary_persona`·`arts/sports/travel_persona`·`hobbies_and_interests`·`professional_persona`·`career_goals_and_ambitions`·`family_persona`·`district`·`housing_type` 등)를 `body_fields`에. 태그 `[Q]`/`[Q-derived]`. **건강 필드(BMI·혈압·혈당·허리둘레·흡연·음주·healthcare_persona)는 쓰지 않는다.**
- **coffee_moments** — 커피가 놓이는 장면 2~3개. 원본 일과·동네·직업·식생활로 장면을 세우고(`[Q-derived]`), 원본에 없는 커피 디테일(어느 브랜드·어디서·키오스크/앱 주문·하루 몇 잔)은 `[가설]`을 붙인다(`[Q-derived]+[가설]`). 원본 서술에 커피·카페가 실제로 나오면 `[Q]` + `quote`(원문 일부 — `verify`가 원본에서 찾는다).
- **brand_biography** — `past`(과거 주 이용 커피 브랜드) → `now`(지금 주 이용) → `next`(컴포즈 재방문·이용 의향) + `story`(원본 생애 맥락 — 취업·이직·결혼·이사·돈 태도와 엮은 서사) + `trigger`(`[INF]`) + **`fgd_probe`**(이 가설을 흔들 질문). 정량 응답이 없으니 태그는 반드시 `[가설]`. **세그 판별 기준과 맞아야 한다**(이탈 세그면 past=컴포즈). 브랜드는 실재 커피 프랜차이즈만, 연령·동네 분포에 개연성 있게.
- **coffee_meaning** — 커피의 역할 하나(보상·연료·쉼·사교·절제·습관·탐험) + 한 줄 + `basis`(원본 필드 — 돈 태도·커리어 목표·big5).
- **adjacent_consumption** — 커피 밖 소비 2건+. 원본 식생활·취미(`[Q]`/`[Q-derived]`), `fusion/trends/` 리포트(`[T:리포트]` + key), 근거 없으면 `[가설]`.
- **voice** — 말버릇·어휘 + 샘플 3문장. 근거 = big5 + 'FGD 화법' 행 + 지역·연령·직업. 원문 말투를 옮기지 않는다.
- **external** — 아래 외부 실측. **audit** — `소스`·`4축`·`오염`·`충돌`·`계측` 5줄.

**룩어라이크 외부 실측 — `fusion/external/`** (`[X:생활시간]` 통계청 생활시간조사 공표 통계표 · `[X:데이터랩]` 네이버 데이터랩)
- 니모트론 셀(성 × 연령대 × 취업 여부 × 가구 형태 — `economic_activity_status`·`family_type`에서)로 같은 조건 집단의 실측을 붙인다. 개인 사실이 아니다 — "나 같은 사람들은 보통 ~"까지만.
  ```python
  import external as X
  cell = X.cell_of(person)                       # {"sex","age","age_band","emp","hh","region"}
  X.time_minutes(cell, "간식 및 음료")           # 성×연령대 행동별 하루 평균 분 (by="emp" → 성×취업, 요일별)
  X.time_clock(cell, "기상", "평일")              # 기상·취침·식사 시작 → coffee_moments의 하루 동선
  X.time_slots(cell, daytype="평일")             # 취업자 '일' 30분 단위 + 전 국민 시간대별 상위 행동
  X.datalab(cell, group="컴포즈커피")              # 커피·컴포즈커피·메가커피·스타벅스·저가커피 — vs_anchor(커피 대비)로 비교
  ```
- 반환값의 `cell`을 그대로 `external[].cell`에 적는다. **`[X:생활시간]`·`[X:데이터랩]` 각각 인물마다 1건+**(verify가 막는다). 데이터랩 기본 파일이 45일 넘게 묵었으면(`X.datalab_freshness()`) Apify 갱신을 제안한다.
- 데이터랩 `ratio`는 상대값이다 — "검색량 N"처럼 쓰지 않는다.

**Apify — 선택 (Apify가 연결된 세션만 · 매번 비용을 보여주고 승인받는다 · 쿠키·로그인 필요한 액터 금지 · 토큰을 어디에도 적지 않는다)**
없으면 이 단락 전체를 건너뛴다 — 실패가 아니다.
- **데이터랩 브리프 키워드** — 브리프에서 1~4개 그룹(동의어 묶음)을 뽑고, 앵커는 기본(커피·카페)을 쓴다. 칸은 패널에 있는 칸만: `X.panel_datalab_cells("<out>/panel.json")`(보통 6~10회, 회당 약 $0.007). `X.apify_datalab_input(groups, g, age, start, end)` → call-actor(`X.APIFY_DATALAB_ACTOR`) → `X.apify_items_to_rows(...)` → `X.write_rows(rows, "<out>/datalab_brief.csv")` → `X.datalab(cell, group=..., path=...)`. 저장소에는 넣지 않는다.
- **인스타 해시태그 · 유튜브 검색** → `[X:인스타]`·`[X:유튜브]`. 브랜드·카테고리·상황 해시태그 3~5개(예: 컴포즈커피·메가커피·저가커피·출근길커피·카공), 유튜브 검색어 2~3개(보통 패널당 $0.4~0.6). `X.ig_input`·`X.yt_input` → `X.save_social(X.instagram_summary(...))`·`X.save_social(X.youtube_summary(...))`. 집계만 남는다(인스타 계정명·본문 없음, 유튜브 상위 채널명 8개·제목까지). sns_use에 인스타그램이 있는 사람은 `instagram.grounding`에 `[X:인스타]` 2건+, 유튜브가 있는 사람은 `media_grounding`에 `[X:유튜브]` 1건+. **인용 값은 요약에 실재해야 한다.**
- **떠오르는 콘텐츠 → `rising_feed`** → `[X:유튜브·급상승]`(`X.YT_CHART_ACTOR`, 무료) · `[X:인스타·급상승]`(시드 `X.panel_interest_seeds(...)` — 니모트론 취미·식생활에서) · `[X:틱톡·급상승]`(`X.TT_ACTOR`, 쿠키 불필요). `X.save_rising(...)`. 인물마다 3~5건 — `match`는 `X.interest_terms(person)`(니모트론 취미·식생활·여가 서술)에 실재하는 단어, sns_use에 없는 플랫폼은 `level: "들어봄"`. "봤다·했다"로 단정하지 않는다.

**충돌 로그**(`meta_fusion["conflicts_current"]`) — 원본↔트렌드(이 사람은 또래 트렌드와 다르다 — 종종 가장 강한 인사이트) · 리포트↔웹 · 잠정 상식 기저 → 근거로 교체. `meta_fusion["sources"]`에 게이트 통과 소스(출처·시점·링크).

**실전 위반 4종 자가 점검** — 2차 통계의 개인화("요즘 ~라던데"는 정상, "그래서 나도 ~했다"는 위반) · 인물 간 디테일 전이 · 원본과 방향이 반대인 서술 · 침묵을 '없음'으로 단정. 여기에 하나 더: **가설을 사실 말투로 쓰기**("10년째 ○○만 마신다" — 원본에 없으면 위반).

**병합·검증·산출**
```python
import fusion as fu
fused = fu.merge("<out>/panel.json", authored, {"brand": "컴포즈 커피", "category": "커피", "sources": [...], "conflicts_current": [...]})
for line in fu.verify(fused, "<out>/panel.json"): print(line)   # 실패하면 AssertionError — 고치기 전엔 산출 금지
fu.save(fused, "<out>")   # personas_fused.json + personas_fused.html
```
`verify`가 막는 것: **보존**(raw·rows·모순·경계·title 변형) · **가설 규율**(brand_biography가 [가설] 아님·fgd_probe 없음, sns_use 근거 태그 없음, coffee_moments `[Q]`인데 원문 인용이 원본에 없음) · **상식 기저**(연령대 불일치·등급↔수치·sns_use와 충돌) · **트렌드**(3건·3축, `[T:리포트]` 0건, key 없음, 적용 연령 밖) · **일기**(7~8줄·트렌드 2줄·개인화·본인 나이 불일치) · **미디어·인스타**(sns_use 미언급, 미이용인데 활동 계정, 세그 내 중복) · **외부 실측**(생활시간·데이터랩 미사용·없는 데이터셋·셀 불일치·데이터랩 절대값) · **소셜·급상승**(근거 부족·지어낸 값·관심사 매칭 실패·미이용 플랫폼 '피드') · **몸체 결합**(4영역·건강 필드·없는 필드·장면 2~3·의미 역할·인접 소비 2·말투 3) · **오염**(해석+가설 > 사실 앵커, 또는 2차층 > 앵커×2 — 앵커 = rows + 인용한 원본 필드 수).
**✅ 통과 라인을 최종 보고에 그대로 옮긴다.**

`personas_fused.html` 화면은 확정된 펼침/접기를 따른다(바꾸지 않는다):
- **펼침(이 순서)**: 일기(트렌드 줄 파란색) · 커피가 놓이는 장면 · 브랜드 전기(주황 [가설] + FGD 검증 질문) · 커피의 의미 · 커피 밖 소비 · 요즘 피드에 뜨는 것 · 미디어 식단 · 인스타그램 프로젝션
- **접기**: 생활 장면 · 트렌드 근거 · 룩어라이크 외부 실측 · 말투 · 상식 기저 · 1차 앵커 · 원본 전체 데이터 · 감사 로그
- 맨 아래 **"FGD에서 검증할 가설"** — 인물별 fgd_probe 모음(모더레이터 가이드 재료).
스크린샷으로 한 번 확인한다.

## 정직성 규칙 (절대 어기지 않는다)

1. **개인의 진짜 태도로 박지 않는다.** 세그 배정은 "가설 운반체"일 뿐, 그 사람이 실제로 그 브랜드를 산다는 주장이 아니다.
2. **브랜드 선호·피처 관심은 사실로 합성하지 않는다.** 이건 조사로 알아낼 대상이다. 7단계 브랜드 전기는 예외가 아니라 이 규칙의 적용이다 — 반드시 `[가설]` 태그 + `fgd_probe`로만 싣고, 사실 말투로 쓰지 않는다.
3. **"최근 N개월 구매자" 같은 라벨은 확인 불가라고 명시.** 니모트론엔 구매 기록이 없다. 캐리어는 "그 세그에 분포상 부합하는 후보"이지 실제 구매자가 아니다.
4. **근거 없으면 지어내지 말고 비참여로 남긴다.** 카드에 신호가 없는 주제는 "관심 없음/모름"이 올바른 값이다. 유창하게 메우는 것이 오염이다. **단 이 규칙은 상식 기저 위에서 작동한다** — 코호트 보편 상식까지 "모름"으로 처리하면 그건 규율이 아니라 상식 위반이다(6단계 'FGD 신빙성 4종' (1)).
5. **합성 속성이 findings로 오해되지 않게** 산출물에 경계(가설·압박테스트 대상)를 명시한다.
6. **니모트론은 19세 이상만 있다.** 미성년(고등학생·초중생) 타깃은 패널에 넣을 수 없다. 그런 브리프면 **학부모(구매결정자) 세그로 대리**하고 그 사실을 산출물에 명시한다 — 조용히 20대로 대체하면 안 된다.
7. **니모트론에 필드가 없는 카테고리(노트북·자동차 등)의 stance는 프록시에 기댄 느슨한 가설**이다. 직업·취미·성격 프록시 + T-배정(예: 폰 브랜드를 연령분포로 확률배정해 생태계 성향 대리)으로 구성하되, **근거가 얇다는 걸 카드에 명시**한다. 근거 두께를 부풀리지 않는 것이 이 스킬의 존재 이유다.
8. **이전 실행의 합성 결과를 카드에 역기입하지 않는다 — 합성은 쌓지 말고, 실측만 쌓아라.** FGD에서 나온 발화는 합성된 개연성이지 그 사람의 사실이 아니다. 그걸 카드에 적어두면 다음 실행의 나는 그것을 사실로 취급하고, 세 번 돌린 뒤엔 카드가 "그가 말한 것"으로 가득한데 그중 아무것도 측정된 적이 없다. 한 세션 안에서 막은 순환이 **시간을 타고 더 은밀하게** 일어나는 형태다 — 태그 붙은 `[INF]`도 몇 달 뒤엔 그냥 '그 사람 이야기'로 보인다. 시의성도 같은 문제다(7월 유행어가 11월엔 낡은 채로 정체성처럼 박힌다). **기록은 쌓되 정체성은 쌓지 않는다**: 산출 HTML/xlsx·토픽 시트·녹취록은 날짜·브리프별 기록으로 남기고, 인물 정체성은 매번 **니모트론 원본 + 스킬에서 재생성**한다. 예외는 **실측뿐** — 소량이라도 실제 설문·실제 FGD로 측정하면 그건 `[Q]` 앵커가 되어 카드를 정당하게 업그레이드한다(합성이 그 아래로 내려간다).
9. **니모트론은 대한민국 전용이다**(`country`=대한민국, KOSIS 정렬). 브리프가 글로벌/해외 시장(예: EAST 중국·태국, LATAM, NA, EMEA)을 타깃하면 **커버 불가를 게이트 A에서 먼저 고지**하고, 한국 슬라이스만 다룬다는 걸 합의한 뒤 진행한다. 한국 패널을 글로벌 인사이트처럼 제시하면 안 된다.

10. **정량이 없다는 것을 숨기지 않는다.** 최종 보고·HTML 상단에 "정량 매칭 없음 — 사실 근거는 니모트론 원본뿐, 주황 태그는 FGD 검증 대상"을 남긴다. 비공개 정량 풀(`compose-nemotron-pool`)의 값·문항을 이 스킬 산출에 섞지 않는다.

## 파이프라인 연결 — 핸드오프 규약

이 스킬의 최종 FGD 입력은 **`personas_fused.json`**(7단계)이다 — `persona-qual-fgd`에 이 파일을 넘기고, 고지할 것: ① `[가설]` 층(brand_biography·sns_use·coffee_moments의 가설 장면)은 흔들려도 되는 가설이다 ② `fgd_probe`·HTML 하단 "FGD에서 검증할 가설"은 모더레이터 가이드 재료다 ③ `fused.common_ground`가 발화 하한선이다. 1차 산출 **`panel.json`**만 넘길 땐 아래 규약대로 — 산출 `panel.json`을 `persona-qual-fgd`(또는 `nemotron-fgd-studio.html`의 '패널 JSON 업로드')가 참여자로 소비 → 모더레이터 가이드 → FGD 실행. 세그 가설을 자극물로 압박 테스트하는 것이 FGD의 역할(선호를 "확인"하는 게 아니라 "어디서 균열나나"를 본다). `[역발상]` 세그가 패널에 있으면 그 사실을 핸드오프 때 고지한다 — FGD에서 정방향 세그와의 **대비 관찰**(브리프 전제가 어디서 깨지나)이 그 세그의 존재 이유다.

**2-b(룩어라이크)로 넘길 땐 패널과 함께 세그별 후보 풀도 넘긴다 — 풀 점검이 끝난 풀만.** `audit_selection(..., handoff=True)`에 🔴가 없어야 하고, 파일은 `selection.save_handoff(recs, "<outputs>/handoff_pool.json", brief=..., rg_note=...)`로 쓴다(형식은 함수 docstring — 세그별 판별 기준·풀 uuid·점검 mode·0점/1점 비율·주의 문구). 넘기는 풀 = `full_read`면 0점을 뺀 풀, `top_read`면 읽은 상위 K 중 1·2점, `sampled`(0점 ≤15%)면 그물 풀 그대로. 핸드오프 고지에 세그별 **풀 크기·점검 mode·0점 비율**을 적는다 — 0점 비율만큼 룩어라이크의 세그 비중이 부풀 수 있다는 뜻이다.

**FGD 소비 측이 알아야 할 것 세 가지** (panel.json을 넘길 때 함께 고지한다 — FGD 스킬은 정량조사 산출을 전제로 설계돼 있어 니모트론 패널에선 이 세 행이 그 자리를 대신한다):
1. **'FGD 화법' 행 = 반응습관(ARS/MRS/ERS)의 대체물.** 화법 차등의 근거로 이 행을 쓰게 하라. 이게 무시되면 소비 측이 "반응습관 데이터 없음 → 전원 균형형"으로 폴백해 좌담회가 밋밋해진다.
2. **'상식 기저' 행 = 발화의 하한선.** "근거 밖 → 모르겠다" 규율은 이 행 **위에서** 작동한다. 상식 기저에 있는 것까지 "모르겠다"로 답하게 두지 마라. **2차 합성을 거친 파일이면 `fused.common_ground`(연령대 통계 근거)가 이 행을 대신한다** — 이 행은 패널 단계 잠정값이다.
3. **스탠스 방향(끌림/저항/양가/유보) = 발화의 방향타.** [Q] 강도만이 아니라 방향까지 카드에 있으니, 발화가 방향을 즉석에서 지어낼 이유가 없다.

**카드에는 안정적 정체성만 담는다.** 니모트론 실제 필드·성격·취미·세그 근거·관여도처럼 잘 변하지 않는 것만. 유행어·지금 뜨는 인물·특정 도구(AI 프로그램 등) 인지도·카테고리 레퍼토리 같은 **토픽 의존적이고 휘발성인 맥락은 카드에 박지 않는다.** 이유 둘:

1. **FGD마다 묻는 게 다르다.** 유행어가 필요한 좌담회와 AI 활용도가 필요한 좌담회에 같은 패널을 써야 한다. 카드에 미리 다 박으면 패널이 한 브리프에 묶이고 비대해진다.
2. **시의성.** 유행어·인물은 몇 달이면 상한다. 7월에 만든 카드로 11월 FGD를 돌리면 낡은 말을 하는 20대가 나온다. **물어보는 시점에 검색해야** 신선하다.

('상식 기저'는 예외가 아니다 — 배달앱·간편결제 같은 코호트 보편 접점은 몇 달로 안 상하는 **안정적 정체성**이라 카드에 실린다. 상하는 건 유행어·인물·신도구 쪽이다.)

덕분에 **카드 하나로 여러 FGD를 돌릴 수 있다** — 같은 패널로 매트리스 좌담회도, AI 도구 좌담회도.

**토픽 맥락은 FGD 시점에 붙인다.** 모더레이터 가이드가 나와 토픽이 확정되면 `references/topic_grounding.md`의 절차로 인물별 **토픽 레퍼토리 시트**를 만들어 참여자에 붙인다. 요약: 웹서치로 **코호트** 레퍼토리 풀 → **개인 카드 신호로 필터** → 각자 다른 레퍼토리 + 각자 다른 인지 경계. **이때도 상식 기저가 우선한다** — '모를 만한 것' 목록에 코호트 보편 대상을 넣으면 안 된다. 경계는 신흥·희소·전문 대상에서만 성립한다.

**가장 중요한 산출은 '아는 것'이 아니라 '모르는 것의 경계'다.** AI 도구 좌담회라면 34세 SW 개발자는 Copilot을 알 만하고, 57세 하역 종사원은 모를 만하다. 이 경계가 비참여를 지키고, 비참여가 분기를 지킨다. 지식을 전원에게 균일 주입하면 9명이 전부 똑똑하게 떠들고 우리가 보존하려던 분기가 증발한다 — 그 순간 FGD는 소비자가 아니라 모델의 예의바름을 보는 일이 된다. **단 경계는 상식 기저 아래로 내려갈 수 없다** — "모른다"가 신빙성을 지키는 건 희소 대상에서고, 보편 대상에선 신빙성을 부순다.

  `python3 signal_scan.py <parquet> --kw 아이돌 뉴진스 --kw2 게임 스팀 --age 19 29`
  `python3 signal_scan.py gh --kw 아이돌 뉴진스 --age 19 29`   ← 로컬 원본 없이(원격 모드)
  `python3 signal_scan.py <parquet> --kw AI 인공지능 --deep`   ← 신호 1% 미만이면 반드시
  `python3 signal_scan.py gh --age 30 69 --deep --body --re "<신호 정규식>" --neg "<제외 문맥 정규식>" --re2 "<2차 정규식>"`   ← 세그 그물(net_patterns.md)을 그대로 스캔. `--neg`는 매칭 전에 비유·금융 문맥을 지우고, `--body`는 신체 서사(수면·통증)를 finance 밖에서만 찾는다

  `python3 selection.py <selection_log.json> --md selection_audit.md --accepted <감수필드> [--handoff]`   ← 2-b로 넘길 패널이면 `--handoff`(풀 점검 없음 🟡, 0점 >15%인데 sampled면 🔴)
